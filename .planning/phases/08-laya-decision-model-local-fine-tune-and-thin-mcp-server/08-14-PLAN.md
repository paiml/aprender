## Interface this plan implements (declared in laya-finetune-gate-v1 1.4.0 and laya-parity-v1 A1)

- recipe.json: optional `seed_selection` {policy, seeds, rank_scale, tie_break}, written for every
  three-seed run and therefore for every production run.
- gate-report.json: `seeds` {declared, n, label, policy, shipped, per_seed[{seed, macro_f1, f_avg,
  ece_post, margin, pass, t_applied, rank_key, eval_probs_sha256, model_safetensors_sha256}]},
  `rescore_noise_sha256`, optional `shift_probe`, `inputs_sha256.shift_jsonl` when shift.jsonl exists.
- rescore-noise.json: schema `laya-rescore-noise-v1` (see the contract's `rescore_noise_schema`).
- Run dir: `seeds/seed-<s>/eval-probs.json` for every gate seed, `shift-probs.json` and
  `shift-zero-shot-probs.json` with shift.jsonl. Exactly one `model.safetensors`, at `checkpoint/`.
