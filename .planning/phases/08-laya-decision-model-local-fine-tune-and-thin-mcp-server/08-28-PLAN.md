Facts: `tool_description` always says "Long texts are truncated by the model itself to its window,
and each such result reports `truncated: true`" next to "at most {max_total_tokens} model tokens over
the whole request"; at the contracted tier max_total_tokens is 120 while a truncated row is always the
agent's max_len (512), so the flag is unreachable (decide-tool-boundary-v1 description says so; the
live tools/list shows both sentences). Every refusal is `pmcp::Error::validation`, but pmcp 2.19.3's
response builder (`server/core.rs`, error_codes::INTERNAL_ERROR) puts it on the wire as JSON-RPC
-32603, while `refusal_names_bound` says "an internal code on any bound refusal is a defect". Its
formula forbids ANY non-empty caller text as a substring, which `texts: ["a"]` makes unsatisfiable.
`classify_admission` claims the (pending + 1)th concurrent request is refused at arrival; pmcp
serialises dispatch, so ClassifyService::call is never concurrent through a transport (the unit tests
call Admission directly). The live function serves the OLD description until a redeploy (plan 08-30).
Rules: pv for the contract; no `.unwrap()`; `$?` never through a pipe; the probe's labels segment
`The labels, in this order: [...]` must not change (plan 08-25 parses it).
Ordering (declared, not incidental): crates/aprender-mcp-decide-lambda/src/probe.rs is edited by plan
08-25 (wave 17) and plan 08-24 (wave 18), both dependencies of this plan. Since 08-24 the Lambda crate
has NO crate-wide `clippy::disallowed_methods` allow: every `json!` call in probe.rs sits in a function
carrying an item-level allow with a reason. Any function this plan adds to or edits in probe.rs (only
under B-iserror) follows the same rule — item-level allow with the reason, never a module-level allow —
and the Lambda clippy gate in Task 3 enforces it.
