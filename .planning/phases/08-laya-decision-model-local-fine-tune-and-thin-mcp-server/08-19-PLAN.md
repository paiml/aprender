<objective>
Close the LOAD side of CR-01 as a class, not a probe: bind every field of the decide-apr-v1 manifest
to the sha-bound source it summarises, inside rung 4, so every consumer of a `Decider` — the stdio
server, the Lambda cold start, verify, inspect-after-08-26 — gets the binding without running verify.

Purpose: `manifest.base.display()` is served as `model.base` in every classify response, and the
manifest's gate / calibration / input-hash fields are what a reader of the artifact sees. Today only
recipe_id, labels, agent and the blob hashes are bound at load (VERIFICATION truth 18). A crafted
.apr can therefore serve a false base identity. The VERIFY side was closed by commit ea940faec
(verify_path refuses bytes the run does not re-pack to); this plan proves it still holds and closes
the load side with a sweep that fails for any manifest leaf that is not bound.

Output: rung-4 cross-checks and one typed refusal, a leaf-sweeping test driven by a contract table,
the contract text made true, a mutation record, and proof that the deployed artifact still loads and
still verifies eligible.
</objective>

Project rules for every task: contracts validated with `pv validate` (via `. scripts/pv_bin.sh`, `$PV`),
never an ad-hoc YAML script; code search with `pmat query`; no `.unwrap()` in production code; the
Bash tool runs zsh (no PIPESTATUS) and `$?` is never read through a pipe; use `rtk proxy <cmd>` where
exact output or exit status matters. Real, gitignored artifacts live in the MAIN checkout, so every
command that touches them resolves `MAIN="$(cd "$(git rev-parse --git-common-dir)/.." && pwd)"` first
(an executor worktree has no `models/` or `data/`).

Interfaces the executor needs (read from source at HEAD 08-VERIFICATION + ea940faec):
- `rung4_structure(reader, manifest) -> Result<Blobs, ArtifactError>` verifies manifest.blobs names ==
  BLOB_TENSORS, each blob's sha256, recipe_id == sha(recipe blob), agent == agent config blob, the
  tensor set, per-entry dtype/size/bounds, task labels == manifest.labels. The recipe and gate-report
  blob bytes are held in `data[4]` and `data[5]` (the latter currently bound to `_gate_report`).
- `load_rungs(bytes, limits, whole_file_sha256)` runs rungs 1-8; `ModelIdentity.base = manifest.base.display()`.
- `pack::Recipe` and `pack::GateReport` are `deny_unknown_fields` serde types of recipe.json and
  gate-report.json; the blobs are those files' exact bytes (pack step 5, `build_manifest`).
- `laya::temperature::temperature_for(agent, qtype, k) -> f32` = clamp(lookup) as f32, lookup =
  temperature_by_options[bucket_key] else temperature[qtype] else 1.0.
- `ladder.rs` helpers: `packed()`, `edit_manifest(bytes, |v: &mut Value|)`, `repack`, `refuse(bytes)`.
Real-weights legs and host memory (revision 2026-09-28): every `just laya-verify`, every armed
laya_parity / fail_closed_vectors / python_records run, the stdio real-model e2e leg, the torch
lifecycle and laya-gates-selftest's default-armed dry run loads multi-GB weights (about 6.3 GB per
laya_parity or laya-verify run), and plans 08-19..08-22 (wave 17) and 08-26 / 08-27 (wave 18) run them
from separate worktrees on one 48 GiB host. Every such command — in `<verify>`, in action steps and in
mutation loops — runs through `heavy`, which serialises them host-wide on one lock file:
`HL=/tmp/aprender-laya-real-weights.lock; heavy() { if command -v flock >/dev/null 2>&1; then flock "$HL" "$@"; else lockf -k "$HL" "$@"; fi; }`
(macOS ships `lockf`, Linux `flock`; pass variables as `heavy env VAR=value cmd`; never nest `heavy`).
A real-weights leg that ends without its verdict line — killed by the OS (`Killed: 9`, exit 137,
lockf's 70) or out of memory — is an environment failure: re-run it under `heavy`. It is never
recorded as a gate refusal, a finding or a mutation RED; only a leg that printed its own verdict or
refusal line counts.
