<objective>
Make Rust and Python compute the gate the same way, bit for bit, as a class: one f64 formula per
quantity with exactly-rounded summation on both sides, declared in the contract, proven on a frozen
case file both languages replay, and extended to the one gate quantity the verifier never recomputed
(f_avg).

Purpose: today Rust recomputes macro-F1 and ECE in f32 while Python uses f64 (numpy). At an exact
threshold the verdicts flip (V7-a: 724 constructed flip pairs; V7-b: 1 in 2000 random sets moves the
rank key), so an honest run can be refused PassDisagrees and the contract's "agree to 1e-12" premise is
false. Fail-closed, but the class is "two implementations of one number", and the fix is to make them
one in both languages.

Output: an exact-sum primitive and f64 metric paths in aprender-core, a bit-level snapshot proving the
shared f32 metrics did not move, metrics.py on math.fsum, the frozen case file, verify on the f64 path
plus check_f_avg, the contract block, and mutation records on both sides.

Sizing note (checker warning, 2026-09-28): this plan touches 11 files in two languages and is estimated
at 185k tokens. It is deliberately NOT split by language: its tracer and its central truth are the
cross-language bit agreement, which only a plan holding both sides can test — Python writes the frozen
expected values that Rust replays, so a Rust-only half could not run its replay and a Python-only half
would prove nothing about Rust. The executor should commit after each numbered step so a context reset
resumes cleanly.
</objective>
