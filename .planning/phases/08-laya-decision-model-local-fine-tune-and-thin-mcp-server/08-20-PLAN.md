Facts from HEAD: `parse_tensor_index_section` reserves `Vec::with_capacity(index_capacity(tensor_count,
remaining))` where `index_capacity = min(tensor_count, remaining / MIN_INDEX_ENTRY_BYTES)` and
`remaining` is bytes to EOF; the sort check refuses only `name[i] < name[i-1]`. `TensorIndexEntry`
holds a String and a Vec (about 72 bytes in memory vs the 20-byte on-disk minimum).
`ModernBertLayer::forward(x, l, config, window)` builds `RopeTable::new(&rope_inv_freq(theta, hd), l)`
before `forward_with_rope` checks `x.len() == l * d`; with l == 0 every check_len passes and
`&qkv[d..]` panics. `ModernBertError::EmptyInput` exists (mod.rs). `unsafe_code = "forbid"` is a
workspace lint, so a counting global allocator is NOT available; the reservation is observed through a
`#[cfg(test)]` thread-local instead.

Rules: no `.unwrap()` in production code; `$?` never through a pipe (zsh, no PIPESTATUS); the base
snapshot for real-weights parity is `$HOME/.cache/huggingface/hub/models--convaiinnovations--laya/snapshots/55cf4c4ebb4ebe31b2550e8bdf3bd21b99753851`.

lifecycle and laya-gates-selftest's default-armed dry run loads multi-GB weights (about 6.3 GB per
laya_parity or laya-verify run), and plans 08-19..08-22 (wave 17) and 08-26 / 08-27 (wave 18) run them
