**The ONE batch builder (B6).** Every model input in this harness goes through a single helper:
```rust
// tests/setfit_conformance.rs
fn batch_from_case(model: &SetFitMiniLm, texts: &[String])
    -> Result<SentenceBatch, SetFitError>
{
    let refs: Vec<&str> = texts.iter().map(String::as_str).collect();
    model.tokenize(&refs)          // the ONLY public batch producer after the D-08 seal
}
```
No submodule constructs a `SentenceBatch` any other way. Each fixture case supplies `texts` and a
`case_id`; the harness asserts the `case_id` resolves in `tokenizer_cases.json` and that the
resolved case's `input_ids` equal the fixture's `input_ids_canonical` AND equal
`batch.input_ids()` — that triple equality is what proves the Rust tokenizer, the fixture, and the
corpus of record all agree, and it is why the ids are still recorded even though the texts drive
the run. `input_ids_slice` is NEVER fed to the model; it exists only so a remap bug can be
diagnosed, because the remap must happen inside the encoder.

Fixture schema: see 01-04 PLAN interfaces block (field names are frozen there; `texts` + `case_id`
on forward_per_layer / pooling_normalize / loss_pair / batch_invariance, `source` on gradients /
optimizer_step).

Per-layer access path (B5): `model.encoder()` (01-07, conformance-gated) ->
`BertSentenceEncoder::forward_tokens_per_layer(&batch)` (01-06, conformance-gated `pub`) ->
`(embeddings_out, layer_outputs)`. `layer_outputs.last()` equals `forward_tokens`'s output and the
fixture's `final_tokens`.

AdamW: impl lives in nn/optim/rm_sprop.rs (struct declared nn/optim/mod.rs:391).
`AdamW::new(params, lr)` defaults betas (0.9, 0.999), eps 1e-8, weight_decay 0.01
(rm_sprop.rs:10-24); builder `.betas(b1,b2).eps(e).weight_decay(wd)`;
`step_with_params(&mut [&mut Tensor])` (rm_sprop.rs:87). Decay is DECOUPLED:
`param -= lr * wd * param` applied before the Adam update (rm_sprop.rs:80) — same ordering as
torch AdamW's `p.mul_(1 - lr*wd)`. Do NOT rely on these defaults in the gate: configure every
hyperparam explicitly from optimizer_step.json (defaults can drift; the fixture is the arbiter).
NOTE: the plain `Adam` struct in nn/optim/mod.rs uses COUPLED L2 decay and defaults wd 0.0 —
wrong optimizer for this gate; use `AdamW`.

**ENC-04 gate semantics (canonical, used by gradient_gate.rs and detach_negative.rs):**
- every named trainable tensor: gradient exists, all elements finite;
- every contracted component (embeddings; per-layer attention; per-layer FFN; per-layer norm):
  aggregate gradient L2 norm > 0;
- per-tensor non-zero required only for names ABSENT from `gradients.json.analytically_zero`;
- names PRESENT in that list must satisfy `max|g| <= ZERO_GRAD_FLOOR` — the exemption is two-sided,
  so an unexpectedly large key-bias gradient is a failure, not a pass.
