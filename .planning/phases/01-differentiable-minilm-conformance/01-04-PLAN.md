Review-driven revisions in this pass (2026-08-08, `/gsd:plan-phase 1 --reviews`):
- **Head boundaries.** The slice now uses 2 heads x 32 dims, not 4 x 16. Slicing hidden 64 into
  four 16-dim heads cuts MiniLM's real 32-dim heads in half, producing a synthetic attention
  structure from real numbers. Two 32-dim heads preserve two complete original head boundaries.
- **Vocabulary remapping is separated from tokenizer identity.** Fixtures carry CANONICAL HF ids
  everywhere a tokenizer boundary is described; `input_ids_slice` is an additional, clearly named
  field, and `vocab_remap.json` is the bridge the slice encoder applies internally.
- **Full-checkpoint -> APR conversion is defined**, not left to the loader to guess:
  `fetch_full_weights.py` now converts and emits a manifest carrying BOTH the source safetensors
  digest and the produced APR digest.
- **Tolerance derivation gains per-family FLOORS** so `10x observed delta` can never yield zero or
  an unrealistically tight value, and separate families for forward / reduction / gradient /
  optimizer reduction-order differences.
- **`gradients.json` gains `analytically_zero[]`** with justifications and a `parameter_order[]`
  ordered array (JSON object key order is not a stable proof of HF ordering).
- **New `activation_reference.json`** so 01-08 can gate exact-GELU parity independently of the
  per-layer FFN outputs, and **`optimizer_step.json` gains expected pre/post loss**.
- **Upstream digests are recorded and verified fail-closed** on every subsequent fetch.

  package.** `crates/aprender-core/Cargo.toml:38` carries a NON-anchored exclude pattern

  `crates/aprender-core/tests/fixtures/setfit/tokenizer.json`, which this plan commits and which

Checker-driven revision, iteration 2 (2026-08-08):

  boundary they are required to exercise.** `forward_per_layer.json`, `pooling_normalize.json`,

Fixture JSON schema (the contract plans 01-05, 01-06 and 01-08 parse against — keep field names exact):

**Corpus-of-record rule (B6).** `tokenizer_cases.json` is the single place where source texts are
defined. EVERY text used by any other fixture MUST appear there as a case. Every other fixture that
a Rust test drives through the model carries (a) a `case_id` equal to that case's `id`, and (b) the
`texts` array repeated verbatim. That pair is what lets 01-08 call
`SetFitMiniLm::tokenize(case.texts)` — the only public batch producer after the D-08 seal — instead
of hand-assembling a `SentenceBatch` from ids and bypassing the tokenizer boundary. The recorded
`input_ids_canonical` must equal the joined case's `input_ids`, and the generator asserts it.

- `tokenizer_cases.json`: `{ "revision": "1110a243...", "tokenizer_sha256": "...", "cases": [ { "id": "case-name", "texts": [".."], "max_length": 256, "input_ids": [[..u32]], "token_type_ids": [[..]], "attention_mask": [[..0/1]], "truncated": [bool], "original_token_counts": [int] } ] }`
  `input_ids` are CANONICAL HF vocabulary ids. Cases must cover: single short text, mixed-length
  pair batch, a >256-token truncation case, CJK text, accented text, mixed-case text — PLUS a case
  for every text consumed by forward_per_layer / pooling_normalize / loss_pair / batch_invariance
  (both `single` and `padded_batch`) / full_model_reference.
  **Padding policy (binding):** pad to LONGEST-IN-BATCH, never `padding='max_length'`. `max_length: 256`
  is a truncation bound only. 01-05 Task 2 asserts exact integer equality against these arrays with no
  tolerance, so a max_length-padded corpus would fail at wave 3 and force a wave-2 fixture + manifest +
  tolerance regeneration — the re-baselining act D-13/D-14 exist to make expensive.
- `slice_config.json`: `{ "num_layers": 2, "hidden": 64, "heads": 2, "head_dim": 32, "intermediate": 256, "vocab": <N~256>, "positions": 64, "layer_norm_eps": 1e-12, "hidden_act": "gelu", "source_revision": "1110a243...", "source_head_indices": [0, 1], "tokenizer_sha256": "..." }`
- `vocab_remap.json`: `{ "orig_to_slice": { "<canonical_id>": <slice_row>, ... }, "slice_to_orig": [<canonical_id>, ...] }` (closure of all token ids used by fixture texts + specials; `slice_to_orig` is the ordered inverse so the slice row order is itself reviewable)
- `upstream_manifest.json`: `{ "revision": "1110a243...", "files": { "config.json": "<sha256>", "tokenizer.json": "<sha256>", "model.safetensors": "<sha256>", "modules.json": "<sha256>", "1_Pooling/config.json": "<sha256>" } }`
- `activation_reference.json`: `{ "op": "gelu_exact", "note": "torch.nn.functional.gelu(x, approximate='none')", "x": [..f32 grid over [-6,6]..], "y": [..], "max_abs_f32_f64_delta": <float> }`
- `forward_per_layer.json`: `{ "cases": [ { "case_id": "<= tokenizer_cases.cases[].id>", "texts": [".."], "input_ids_canonical": [[..]], "input_ids_slice": [[..]], "attention_mask": [[..]], "shape": { "batch": B, "seq": S, "hidden": 64 }, "embeddings_out": [...], "layer_outputs": [ [...], [...] ], "final_tokens": [...] } ] }` (row-major flattened arrays; `shape` is explicit). `final_tokens` equals `layer_outputs[last]` — recorded separately so a Rust mismatch can name whether it diverged at the embedding, at a layer index, or at the final state.
- `pooling_normalize.json`: `{ "cases": [ { "case_id": "..", "texts": [".."], "input_ids_canonical": [[..]], "attention_mask": [[..]], "shape": { "batch": B, "hidden": 64 }, "pooled": [...], "normalized": [...] } ] }`
- `loss_pair.json`: `{ "pair": { "a_case_id": "..", "a_texts": [".."], "a_ids_canonical": [[..]], "a_ids_slice": [[..]], "a_mask": [[..]], "b_case_id": "..", "b_texts": [".."], "b_ids_canonical": [[..]], "b_ids_slice": [[..]], "b_mask": [[..]], "labels": [0.0/1.0, ..] }, "cosine": [..], "mse": <scalar> }` — a non-degenerate pair batch; `a_texts`/`b_texts` are what 01-08 tokenizes to rebuild it.
- `gradients.json`: `{ "source": { "fixture": "loss_pair.json", "a_case_id": "..", "b_case_id": ".." }, "parameter_order": ["<hf_dotted_name>", ...], "grads": { "<hf_dotted_name>": {"shape": [..], "grad": [..]} }, "zero_grad_floor": <float>, "analytically_zero": [ { "name": "encoder.layer.0.attention.self.key.bias", "max_abs_grad": <float>, "justification": "key bias adds a constant to every key; softmax is invariant under a constant shift of all logits" } ] }` — for ALL slice parameters, `pooler.*` excluded. `source` names the batch these gradients were recorded on, so the Rust gate rebuilds the SAME batch from texts.
- `optimizer_step.json`: `{ "source": { "fixture": "loss_pair.json", "a_case_id": "..", "b_case_id": ".." }, "adamw": {"lr": 2e-5, "betas": [0.9, 0.999], "eps": 1e-8, "weight_decay": 0.01}, "loss_before": <float>, "loss_after": <float>, "post_step": { "<hf_dotted_name>": [..] } }` — ALL parameters trainable (no frozen groups; the frozen proof is Rust-internal, see 01-08)
- `batch_invariance.json`: `{ "single": { "case_id": "..", "texts": [".."], "input_ids_canonical": [[..]], "attention_mask": [[..]], "embedding": [..64..] }, "padded_batch": { "case_id": "..", "texts": [".."x3], "input_ids_canonical": [[..]x3], "attention_mask": [[..]x3], "embeddings": [...], "target_row": <index of the sentence that also appears in `single`> } }` — NOTE: `case_id` lives on EACH of `single` and `padded_batch` (mirroring `loss_pair`'s `a_case_id`/`b_case_id`), never as one top-level id: the two batches hold different text sets and cannot resolve to a single tokenizer case. Both `case_id`s must exist in `tokenizer_cases.json`. — the same sentence encoded at batch 1 and inside a padded batch-3. Both `texts` arrays are tokenized by the Rust side; `target_row` says which padded row to compare.
- `full_model_reference.json`: `{ "case_id": "..", "texts": [".."x3], "embeddings": [...] }` — 3 sentences -> final [3,384] normalized embeddings from the FULL pinned model (feeds the D-10 gated suite)
- `tolerances_measured.json`: `{ "<fixture_family>": {"max_abs_f32_f64_delta": x, "floor": f, "recommended_tolerance": y} }` where `y = max(10*x, f)`
