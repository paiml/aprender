## Review corrections incorporated (02-REVIEWS.md)

- **V1 / Codex blocking #2 (adjudicated claim #1 — Gemini was WRONG, Codex CONFIRMED) — profile
  isolation was runtime-only, so the promised trybuild proof could not exist.** The previous
  design put `profile` as a runtime field on `SplitDeclaration` while `from_jsonl_bytes` was
  generic over `R`, so `Split::<Validation>::from_jsonl_bytes(bytes, &compat_decl)` COMPILED and
  returned `Err(ConflictingSourceRole)`. trybuild proves NON-compilation, so plan 02-08's
  compile-fail snapshot was unobtainable and DATA-06's headline claim was unproven. **Fixed:**
  profile is a type parameter. `PreparedDataset<Canonical>` and `PreparedDataset<Compatibility>`
  are distinct types with distinct constructors; only the canonical type has a
  `validation_witness()` method; selection (plan 02-05) consumes `&PreparedDataset<Canonical>`.
  Passing a compatibility dataset to selection is a type error, and calling
  `validation_witness()` on it is a "no method named" error — both genuinely non-compiling.
- **V1 second half / Codex 02-03 HIGH — a compatibility `Split<Train>` could borrow an unrelated
  canonical `Split<Validation>`.** Fixed by the same change: train, validation, test, exclusions,
  fingerprint, and ledger records live inside ONE `PreparedDataset` value, so there is no API that
  accepts two independently-constructed splits.
- **V4 / Codex 02-03 HIGH (adjudicated claim #4) — the plan contradicted itself on the ledger.**
  The old interface block declared `from_jsonl_bytes(bytes, decl)` with no ledger parameter while
  the behavior block required every ingest to append to "a caller-supplied `&mut AccessLedger`".
  **Fixed by picking one:** the per-split constructors are `pub(crate)` and take no ledger; the
  PUBLIC `PreparedDataset` constructors take `&mut AccessLedger` and record once per split. The
  interfaces block below and the behavior blocks now agree.
- **F8 / Codex 02-03 HIGH — exact and normalized duplicate matches must be coalesced.** An exact
  duplicate necessarily shares a normalized hash, so grouping independently by both keys
  double-counts and can double-decrement the training pool. Task 3 builds connected components
  (union-find) over the union of both edge kinds; each component is one group recording which
  detection kinds fired.
- **Codex 02-03 MEDIUM — `others: &[&[LabeledExample]]` lost typed role/profile information.**
  Removed: dedup now runs INSIDE the `PreparedDataset` constructor over its own typed splits, so
  no untyped slice-of-slices crosses the API.
- **Codex 02-03 MEDIUM — validation did not require `label_text == label_names[label]`.** Now an
  explicit gate returning `LabelTextMismatch`.
- **Codex 02-03 MEDIUM — the dataset fingerprint omitted identity fields.** Widened to cover IDs,
  roles, profile, label map, normalization version, per-row exact hashes, per-split source hashes,
  and per-class counts.
- **D-27 (new locked decision) — implemented here.** Prepare-time duplicate *content* is
  excluded-and-recorded and never fatal (D-18 verbatim). Typed failure is reserved for split-role
  span and for pool exhaustion. Both halves are asserted by tests in this plan.

## Checker corrections (iteration 3)

- **Blocker — `hash.rs` reached forward into `split.rs`.** The previous revision gave
  `SplitFingerprint::compute` the signature `<R: SplitRole>(split: &Split<R>)`, but `Split` and
  `SplitRole` are produced by Task 2 while `hash.rs` belongs to Task 1, whose `<files>` is only
  `schema.rs, hash.rs`. Task 1's gate compiles the crate, so it could not pass; and Task 1's
  one-split distinctness criterion needed a `Split<R>` value that did not yet exist. Secondarily,
  `DatasetFingerprintInput` was NAMED in the interfaces block and defined nowhere in the phase.
  **Fixed with option (a):** both fingerprints now take symmetric raw-parts inputs —
  `SplitFingerprintInput` and `DatasetFingerprintInput`, BOTH defined explicitly — and both route
  through one shared private per-split absorption helper, so "the same construction" is literally
  true. hash.rs stays a pure leaf with no dependency on the typestate; Task 3 assembles the inputs
  from its typed splits, and that assembly is the single point where the two meet. Option (b)
  (moving `SplitFingerprint` into Task 2) was rejected: it would have split one hashing story across
  two tasks and left `hash.rs` importing `split.rs`.
- **D-07 traceability.** D-07 scopes DATA-02's remaining work to exactly three classes — duplicate
  IDs, cross-split duplicate *content*, and conflicting source roles — and this plan is where all
  three land: Gate 3 and Gate 2 of Task 2's ladder, and Task 3's `coalesced_exclusions`. Cited here
  so execution reads the scope from the locked decision rather than re-deriving it from DATA-02's
  requirement text.

## Checker corrections (iteration 2)

- **Warning 1 — `validation_fingerprint` was vacuous.** `ValidationWitness::fingerprint_hex`
  returned the dataset's OWN fingerprint, so plan 02-05's payload recorded the same value under
  two names and two of its twelve rejection tests were the same test. Fixed: `hash.rs` now also
  provides a domain-tagged `SplitFingerprint`, `fingerprint_hex()` returns the validation split's

- **Warning 3 — `Split::from_rows`'s `source_hash` derivation was unspecified.** Plan 02-06

/// with a SplitFingerprint even for a one-split dataset.
pub struct DatasetFingerprint([u8; 32]);
impl DatasetFingerprint {
    pub fn hex(&self) -> String;
    /// profile, ordered label names, normalization version, then for each split in ascending role
    /// order: role name, source hash, per-class counts, and its (id, exact_hash) pairs sorted by id.
    pub(crate) fn compute(input: &DatasetFingerprintInput<'_>) -> Self;
}
/// Identity of ONE split alone. Domain-tagged `b"apr-split-fp-v1\0"`.
/// This is what `ValidationWitness::fingerprint_hex` returns — see the note there.
/// It takes the SAME raw parts as one element of `DatasetFingerprintInput::splits`, which is what
/// makes "the same construction, a different domain tag" literally true rather than approximate —
/// both routes call one shared private per-split absorption helper.
pub struct SplitFingerprint([u8; 32]);
impl SplitFingerprint {
    pub fn hex(&self) -> String;
    pub(crate) fn compute(input: &SplitFingerprintInput<'_>) -> Self;
}
