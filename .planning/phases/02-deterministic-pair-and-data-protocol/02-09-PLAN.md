## Review corrections incorporated (02-REVIEWS.md)

Codex rated this plan HIGH: "the user surface can bypass provenance and compatibility isolation
even if the lower-level happy-path tests pass." Every finding is addressed.

- **F16 / Codex 02-09 HIGH — the command read JSONL with hardcoded declarations and validated
  neither `benchmark-manifest.json`, nor its profile, source hashes, schema version, nor split
  hashes, so a mixed or forged directory could pass row-level checks.** Both commands now ingest
  through the crate-owned `PreparedDataset::<Canonical>::from_attested_bytes` boundary that plan
  02-06 Task 1 delivers (it was Task 2 before the checker-blocker-2 reorder put `attestation.rs`
  first — corrected here so the citation matches the plan it points at). A compatibility directory
  fails `ProfileMismatch`; a mixed directory
  fails `SplitHashMismatch`; a stale directory fails `UnsupportedSchemaVersion`.
- **F6 / Codex 02-09 HIGH — `Selection::from_manifest` was insufficiently strict, so delegating to
  it did not close the replay hole.** Plan 02-05 replaced it with `Selection::replay`, which
  consumes a canonical prepared dataset and revalidates every invariant including a deterministic
  recomputation. `run_pairs` calls only that.
- **F7 / Codex 02-09 HIGH — the access ledger was never persisted.** It is now part of the
  selection-manifest payload (plan 02-05), so `apr data select` writing the manifest IS the
  persistence, and `--json` surfaces it.
- **F16 / Codex 02-09 HIGH — pair dumps lacked no-clobber, atomic write, and rollback.** Every
  write in this module is temp-file + `write_all` + `sync_all` + `rename` within the destination
  directory, with `create_new` no-clobber semantics, `--force` to replace, and temp cleanup on any
  error path. Tested with an induced mid-write failure.
- **F3 / Codex 02-09 MEDIUM — explicit budget versus hard cap remained ambiguous at the CLI.**
  Resolved to match plan 02-07's `budget_resolution`: `--budget` above `--hard-cap` is an error
  naming both numbers and suggesting `--hard-cap`, never a silent clamp. The help text says so.
- **F16 / Codex 02-09 MEDIUM — selection defaulted to seed 42, which is not one of the ten
  contracted benchmark seeds.** Verified: `crates/apr-cli/src/commands/data_tweeteval.rs:45`
  defines `BENCHMARK_SEEDS: [u64; 10] = [13, 17, 23, 29, 31, 37, 41, 43, 47, 53]`. `--seed` is now
  REQUIRED with no default and is validated against that list; `--any-seed` is the explicit,
  documented escape hatch for experimentation, and the manifest records which mode was used.
- **Codex 02-09 LOW — generic command names are misleading if the implementation is hardcoded to
  TweetEval declarations.** Addressed honestly: the declarations come from the attested benchmark
  manifest in the data directory rather than from hardcoded TweetEval constants, so the commands
  are as generic as their name; the help text states which manifest field supplies the label map
  and counts.
