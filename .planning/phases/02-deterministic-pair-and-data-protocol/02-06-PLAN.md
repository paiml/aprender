## Review corrections incorporated (02-REVIEWS.md)

- **Codex blocking #3 / F-seam — "the TweetEval refactor has no viable ETL seam".** Codex was
  right that the previous plan text could not be implemented: it claimed to relocate "the raw
  parsing ladder, text/label alignment, label parsing, and count validation" into a crate that
  only ingests JSONL, while upstream TweetEval ships paired `*_text.txt` / `*_labels.txt`. The
  orchestrator resolved this against locked **D-05**, which already picks the seam: the crate owns
  "labeled-example schema, typed split roles, JSONL read/write, per-row content hashes, dataset
  fingerprint, cross-split duplicate detection", and `apr-cli` keeps "URLs, filenames, expected
  counts, label names, clap args, and the `ureq` network fetch". **Paired text/label decoding is
  TweetEval-specific and stays CLI-side.** This plan's Task 1 text is corrected to match D-05
  rather than inventing a new seam: `decode_utf8`, line splitting, the text/label length check,
  label integer parsing, `LABEL_NAMES` lookup, and `{split}:{index}` ID minting remain in
  `data_tweeteval.rs`; what moves is everything downstream of `Vec<LabeledExample>`.
- **F16 / Codex 02-09 HIGH — nothing validated `benchmark-manifest.json`, its profile, source
  hashes, schema version, or split hashes, so a mixed or forged directory could pass row-level
  checks.** **Task 1** adds the crate-owned `DatasetAttestation` + `from_attested_bytes` boundary
  that plan 02-09's commands must go through. It lives here because this is the plan that owns the
  benchmark-manifest format.
- **F8 (consequence) / Codex 02-06 HIGH — "exactly one group" could become two.** Now guaranteed
  by plan 02-03's union-find coalescing; the real-data golden asserts `groups().len() == 1` and a
  pool decrement of exactly one, which is the assertion that would have failed under the old
  independent-grouping design.
- **V2 / Codex 02-06 MEDIUM — `pv diff ... HEAD` is invalid.** Task 3 materializes the old
  contract with `git show <rev>:<path> > /tmp/…` and diffs two real files.
- **F22 / Codex 02-06 MEDIUM — schema version 2 was introduced with no old-version policy.**
  Defined explicitly, and CRATE-side after this revision: `attestation.rs` (Task 1) owns
  `SUPPORTED_DATASET_ATTESTATION_SCHEMA_VERSIONS = [2]`, and Task 2's CLI read references that
  constant. A version-1 manifest is `UnsupportedSchemaVersion` with a message telling the user to
  re-prepare. There is deliberately NO migration shim, because a version-1 manifest predates the
  exclusion record and any synthesized value would be an unattested guess.
- **Codex 02-06 MEDIUM — "every prior test unmodified" could block necessary assertions about the
  intentional schema change.** Relaxed precisely: no pre-existing test may be DELETED or have its
  assertions weakened, and the test-name set must not shrink; a pre-existing test that pins
  `schema_version: 1` may be updated to 2 with the change called out explicitly in the SUMMARY.

## Checker corrections (this revision)

  Task 1 embedded "Task 2's serialized form" (`DatasetAttestation`) into the benchmark manifest and

  exist until Task 2, so Task 1's `<automated>` (`cargo check -p apr-cli`,
  `cargo test -p apr-cli --lib data_tweeteval`) could not compile. **Fixed by REORDERING:**
  `attestation.rs` is now Task 1 and the `data_tweeteval.rs` adapter refactor is Task 2. The
  `dataset_attestation` manifest section stays with the refactor, where it belongs, and now
  consumes a type that already exists. `files_modified`, the threat-model task references, and
  02-VALIDATION.md's per-task rows are updated to match.

  attestation's `schema_version` against "the supported set", but the only constant the plan
  defined (`SUPPORTED_BENCHMARK_SCHEMA_VERSIONS`) was declared CLI-side in the refactor task —

  are now crate-owned too: `attestation.rs` (Task 1) defines
  `DATASET_ATTESTATION_SCHEMA_VERSION` and `SUPPORTED_DATASET_ATTESTATION_SCHEMA_VERSIONS`, and
  the CLI's benchmark-manifest `schema_version` REFERENCES the crate constant rather than
  declaring a parallel one.
