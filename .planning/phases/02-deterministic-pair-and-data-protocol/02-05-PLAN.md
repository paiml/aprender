## Review corrections incorporated (02-REVIEWS.md)

- **F4 / Codex 02-05 HIGH — the semantic hash was defined circularly.**
  `semantic_hash == SHA256(to_canonical_bytes())` cannot hold if the canonical bytes contain the
  `semantic_hash` field, which the old schema implied. **Fixed:** `SelectionPayload` is the hashed
  object and contains no digest; `SelectionManifest` is the outer envelope holding
  `semantic_hash`, the payload, and the unhashed volatile block.
- **F4 second half / Codex 02-05 HIGH — the hashed payload excluded provenance and algorithm
  fields.** Widened to schema_version, algorithm_version, profile, dataset_fingerprint,
  validation_fingerprint, label map, normalization version, exclusion record, root_seed,
  shots_per_class, the ordered SelectedExample list, and the ledger hash.
- **F5 / Codex 02-05 HIGH — `SelectedId` was consumed by plan 02-07 but never defined, and
  `Selection` did not clearly retain a label per selected ID.** Both defined here:
  `SelectedExample { id, label, exact_hash, normalized_hash }` and an opaque `SelectedId` ordinal
  with a private constructor, plus `label_of` / `id_of` / `selected_id` accessors. Class-size
  totals alone are an unsafe basis for pair targets.
- **F6 / Codex 02-05 HIGH — `Selection::from_manifest` was too weak, so a forged compatibility
  manifest could bypass selection-time isolation.** Replaced by
  `Selection::replay(&SelectionManifest, &PreparedDataset<Canonical>)`, which cannot even be
  handed a compatibility dataset (the type forbids it) and revalidates every selection invariant
  including a full deterministic recomputation of the ordered list.
- **F7 / Codex 02-05 HIGH (cross-plan) — the access ledger was created but never persisted, so
  Phase 5's selection-lock had nothing to read.** The ledger's records and hash are now inside the
  hashed selection payload.
- **F21 / Codex 02-05 MEDIUM + Gemini §4.3 — RNG byte encoding was underspecified.** `derive_key`
  freezes the domain tag, little-endian seed bytes, and little-endian 64-bit truncation; the
  64-bit lane assembly (`lanes[1] << 32 | lanes[0]`) is stated; the six domain strings are frozen
  in the contract and referenced by name here.
- **F21 second half / Codex 02-05 MEDIUM — `bounded(..., n)` accepted `n == 0` and could not
  report an error.** `bounded` now takes `NonZeroU64`, making a zero bound unrepresentable.
- **Codex 02-05 LOW — mapping invalid shot counts to `InvalidClassCounts` weakened diagnostics.**
  A dedicated `InvalidShots { got, allowed }` variant ships (added in plan 02-02).
- **V1 consequence — the selection signature changed** from `(&Split<Train>, &Split<Validation>, …)`
  to `(&PreparedDataset<Canonical>, …)`. This is what removes the witness-mixing hole and what
  makes plan 02-08's trybuild cases actually non-compiling.

// rng.rs — every random decision in the crate flows through these functions
pub struct DomainKey([u32; 2]);
/// key = trunc64_le(SHA-256(DOMAIN_TAG ‖ root_seed.to_le_bytes() ‖ domain.as_bytes()))
/// DOMAIN_TAG = b"apr-contrastive-v1\0"; the 64-bit truncation is
/// [u32::from_le_bytes(d[0..4]), u32::from_le_bytes(d[4..8])] — LITTLE-ENDIAN, frozen.
pub fn derive_key(root_seed: u64, domain: &str) -> DomainKey;
/// counter = [ordinal as u32, (ordinal >> 32) as u32, stream_id, 0]; pure in its arguments.
pub fn draw(key: &DomainKey, stream_id: u32, ordinal: u64) -> [u32; 4];
/// Assembles a u64 from a draw as ((lanes[1] as u64) << 32) | (lanes[0] as u64) — lane 0 is the
/// LOW half, frozen — then multiply-shift: ((x as u128 * n.get() as u128) >> 64) as u64.
/// `n` is NonZeroU64 so a zero bound is unrepresentable (review finding F21).
pub fn bounded(key: &DomainKey, stream_id: u32, ordinal: u64, n: NonZeroU64) -> u64;

}

pub struct SelectionManifest {
    pub semantic_hash: String,        // hex of SHA-256(payload.to_canonical_bytes())

}

    /// returning (else SemanticHashMismatch). Volatile fields never affect the digest.
    pub fn from_bytes(bytes: &[u8]) -> Result<Self, ContrastiveDataError>;
}
