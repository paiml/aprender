**Review fix 1 — no gradient clearing.** The first draft's loop was
`backward -> grad norms -> clip -> step_refs -> scheduler step`, with no `zero_grad`. Given
`accumulate_grad`, step N's gradient would be the sum of steps 0..N. This is a correctness defect,
not a style one.

**Review fix 2 — scheduler applied after the optimizer.** As drafted, AdamW was constructed at
`config.encoder_lr` and the scheduler stepped AFTER `step_refs`, so step 0 ran at the peak LR and
warmup never applied. The corrected order applies the scheduled LR BEFORE the step and advances
AFTER it. Note the reference consequence, pinned in 03-03: with warmup_steps > 0 the scheduled LR at
step 0 is exactly 0.0, matching HF's LambdaLR. That is fidelity, not an off-by-one — do not "fix" it.

**Review fix 3 — both pair-side forwards shared one step counter.** They now carry distinct forward
ordinals `2*step + 0` and `2*step + 1` (D-15's `block`), so branch A and branch B draw independent
dropout masks.

**Review fix 4 — pair-order and batch-boundary digests were RECOMPUTED from configuration.** Two
runs that consume the same WRONG order would then reproduce perfectly and report the expected
digest. The loop now hashes what it actually consumed, in band.

**Review fix 5 — `||dTheta|| / ||theta_init||` is undefined at zero init**, and a whole-table
denominator makes the sparse embedding class's ratio a function of vocabulary size, so a
fixture-calibrated epsilon cannot transfer. Both are fixed by the support-restricted,
floor-protected denominator below.

**Review fix 6 — initial norms alone cannot produce `||theta_final - theta_init||`.** Full initial
tensor snapshots are required; their memory cost is now planned and recorded.

**Review fix 7 — AdamW moment state is positional**, so the parameter registry order must be proven
stable across steps.

**Review fix 8 — device and max_length were validated but never consumed.**
