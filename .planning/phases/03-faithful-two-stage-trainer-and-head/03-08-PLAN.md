<decision_note>
**Sealing the codec trait is the conservative default taken here, and the user should confirm its
Phase 4 consequence.** Sealing later is a breaking change; un-sealing later is not — so Phase 3
seals. The consequence is that Phase 4's APR codec lands as a thin ADAPTER module inside
`aprender-train/src/train/setfit/` (adding `impl Sealed for AprCodec`) that calls `aprender-core`'s
APR format code. The APR FORMAT still lives in aprender-core; only the adapter moves. D-07 was
amended in the phase-3 review run to record this. If the user prefers the codec trait to be openly
implementable from any crate, un-seal it — the policy/codec split alone already removes the
comparison and minting powers from implementors, which is the substantive half of the fix.
</decision_note>
