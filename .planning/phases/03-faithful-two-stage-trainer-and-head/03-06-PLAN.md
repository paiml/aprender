<decision_note>
**USER DECISION — the calibrated regime is FIXTURE-ONLY, and the gate FAILS CLOSED outside it.**
Only the fixture encoder's architecture fingerprint enters `CALIBRATED_REGIMES`. A run against the
real pinned `all-MiniLM-L6-v2` therefore does NOT get a pass/fail verdict — it gets
`UncalibratedRegime` and stops. That is the intended behaviour, not a gap: an epsilon measured on a
2-layer/64-hidden/97-vocab slice is not evidence about a 6-layer/384-hidden/30522-vocab model, and
the support-restricted denominator makes the sparse class dimension-invariant in ARGUMENT, not in
measurement.

**Consequence, stated here because this is where it will actually be read:** Phase 5's benchmark
cells run the production encoder, so they are BLOCKED by this gate until someone calibrates on the
production encoder and adds its fingerprint to the contract's calibrated set. Per D-10(c) that is a
deliberate contract edit `pv diff` flags — it is not a code change, not a threshold relaxation, and
not something a Phase 5 executor may do inline to unblock a benchmark run. The same note is recorded
against Phase 5 in `.planning/ROADMAP.md` so the dependency is visible at roadmap level and not only
inside a Phase 3 plan.
</decision_note>
