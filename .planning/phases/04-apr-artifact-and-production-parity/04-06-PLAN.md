<objective>
Ship `apr setfit train` (D-05): a dedicated namespace cloned from the `apr data` template, whose
command is a pure filesystem adapter — config file in (D-07), Phase 2 prepared dataset + selection
manifest in, verified `setfit-apr-v1` out via `verify_artifact(AprCodec)`, atomic write, JSON/human
report with the artifact hash — plus the ONE bounded artifact-reading helper every later apr-cli
surface is required to use.

Purpose: OPS-02's train leg; OPS-06's fail-closed device gate at the CLI boundary. The namespace
stays training-only (D-06) — predict/eval/inspect are generic commands (04-07).

**Review findings closed here.** The HIGH finding that this plan's override path required a
private serde wire type an external crate cannot name: overrides now go through
`SetFitTrainConfig::to_request` (public, landed by 04-14) into the single validating constructor,
and that API work is in the dependency graph rather than assumed. B5's CLI half: this plan creates
`setfit_io::read_setfit_apr_file_bounded`, so 04-07 and 04-08 consume a bounded reader instead of
each writing `fs::read`.

Output: apr-cli `setfit` feature, SetfitCommands enum + dispatch, setfit_io.rs, setfit_train.rs
adapter + tests.

Branch: `gsd/phase-4-apr-parity`. Wave 5, parallel with 04-12 and 04-16 (both aprender-train).
