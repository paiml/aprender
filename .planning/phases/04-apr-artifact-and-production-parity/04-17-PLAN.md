<objective>
Land the two public-API doors that wave 5 proved missing, so 04-12, 04-16 and 04-06's write leg
can complete. Both gaps were established with rustc during wave 5 (probes compiled, then deleted),
and G1 was found independently by all three wave-5 agents.

**G1 — the artifact bytes have no public door.** `verify::run_verify_policy` does `drop(bytes)`
(verify.rs:655) and keeps only `bytes.len()`. `VerifyReport::artifact_bytes()` returns a `usize`,
which is the trap: it compiles and reads as if the bytes were in hand. `SetFitBundle::from_run_parts`
is `pub(crate)`, so the public codec seam is not a way around it. Net effect today:
`apr setfit train` can report the artifact's SHA-256 and cannot write the file that digest is of.

**G2 — the lock doors are typed against the train-time run.** `create_selection_lock`,
`mint_test_token` and `CanonicalTestAccess::grant` all require `SetFitRun<ArtifactReloadedAndVerified>`,
whose only producer consumes a live `SetFitRun<HeadFitted>`. That state is NOT reconstructible from
artifact bytes: `HeadFittedEvidence` has seven fields of which five are unrecoverable, and
`PassedEvidence` is mintable only by `tune::validate_evidence`, which needs the full `UpdateEvidence`
table — which the artifact deliberately carries as a hash (bundle field 19 is `EvidenceSummary`).

The decisive measurement, re-verified at plan time: those three doors read exactly
`artifact_hash()`, `selection_semantic_hash()` and `selection().ledger_hash()` off the run.
**Not one of them touches the evidence table.** So the blocker is TYPING, not missing data — which
is why the fix is a sealed credential rather than a schema change. This is 04-CONTEXT.md D-11 as
already written ("a fresh process's verified state is integrity + probe replay"), and it keeps the
artifact schema, `setfit-apr-v1.yaml` and the 20-field bijection gate completely untouched.

This plan lands ONLY the two doors. It does NOT write `reload_verified_run_from_apr` — that stays
04-16's job, built on top of the credential.
</objective>

## Task 1 — G1: retain the verified bytes, hand them out once

1. Add a `bytes: Vec<u8>` field to `VerifiedOutcome` (verify.rs:599). Move `bytes` into it instead

   move so `VerifyReport` is unchanged.
2. **Do not move `drop(reloaded)`.** It is the larger buffer (~2x artifact size, tensors as hex)
   and its drop must keep its current position.
3. Rewrite the comment block at verify.rs:650-655. It currently justifies dropping ~180 MB. That
   justification is now partly false, and a measured claim must not be left standing wrong.
   State what is retained, why (the caller has no other route to the verified bytes), and the
   measured peak delta from step 5.
4. Add `into_artifact_bytes(self) -> Vec<u8>` on `SetFitRun<ArtifactReloadedAndVerified>` in mod.rs,
   next to the existing accessor block. Add NO borrowing accessor.
5. **Measure, don't assume.** Record peak RSS for one full verify before and after this change
   (e.g. `/usr/bin/time -l` on the existing lifecycle or repro test, or a `#[ignore]`d bench).
   Put the two numbers and the delta in the SUMMARY. If the delta materially exceeds the ~180 MB
   the old comment cited, say so plainly rather than rounding it away.

   `sha256(run.artifact_hash_hex())` must equal `sha256_hex(into_artifact_bytes())`. A test that
