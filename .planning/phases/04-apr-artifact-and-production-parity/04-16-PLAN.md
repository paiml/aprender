<replan_note>
**RETARGETED after the wave-5 block (user decision at the wave-5 checkpoint).**

This plan's original approach — rebuild `SetFitRun<HeadFitted>` from artifact bytes and re-enter
`verify_artifact` — is PROVEN IMPOSSIBLE, not merely hard. rustc said so during wave 5:
`E0063` (HeadFittedEvidence has seven fields, five unrecoverable) and `E0451` (PassedEvidence's
fields are private; only `tune::validate_evidence` mints it, and it needs the full UpdateEvidence
table, which the artifact deliberately carries only as a hash). See `04-16-BLOCKED.md`.

The chosen fix is the SEALED CREDENTIAL, landing in 04-17. Therefore, in this plan:

- Step 3's provenance identity gate is KEPT VERBATIM. It is still the right gate and still this
  plan's core value: refuse the artifact when the recorded selection semantic hash, selection
  ledger hash or dataset fingerprint disagrees with the supplied selection and dataset, typed,
  each error naming both values.
- Steps 4-8 (rebuild the run's parts, re-enter verify_artifact) are DROPPED. Do not attempt them.
- `reload_verified_run_from_apr` no longer returns `SetFitRun<ArtifactReloadedAndVerified>`.
  It returns a fresh-process credential built from `load_setfit_apr` (which already runs the full
  production loader ladder including probe replay) plus the step-3 identity gate. That credential
  is what 04-17's retyped `create_selection_lock` / `mint_test_token` / `grant` accept.
- The must_haves truth "A FRESH process can obtain a SetFitRun<ArtifactReloadedAndVerified>" is
  superseded: the requirement was always REACHING THE LOCK DOORS, and D-11 already defines a fresh
  process's verified state as integrity + probe replay. Reaching them via the credential satisfies
  APR-04 and TRN-07 without fabricating one field of evidence.
- The "no second minting path / no second tolerance" truth still binds, and binds harder: do not
  construct `HeadFittedEvidence` or `PassedEvidence` by any route.
</replan_note>

<objective>
Close a gap the cross-AI review exposed indirectly and that plan-time code reading confirmed
outright: `SetFitRun::verify_artifact` is the ONLY producer of
`SetFitRun<ArtifactReloadedAndVerified>` and it consumes a live, just-trained
`SetFitRun<HeadFitted>`. There is no path from artifact bytes to that state. But
`create_selection_lock`, `mint_test_token` and `CanonicalTestAccess::grant` are all methods on
`SetFitRun<ArtifactReloadedAndVerified>` — so a separate `apr eval` process, which is exactly
D-16/TRN-07's "a user can" tier, cannot reach any of them. 04-07 as previously written referenced a
"Ph3 bytes-reconstruction path" that does not exist.

The fix deliberately does NOT add a second minting policy. It rebuilds the run's parts from the
artifact and then re-enters the existing trusted `verify_artifact` policy verbatim, which closes,
hashes, drops, deserializes, closure-checks, rebuilds, re-probes and compares at `Tolerance::EXACT`
exactly as it does at train time. The reload therefore inherits every guarantee the policy already
proves, and adds two of its own: a provenance identity gate over all three recorded identifiers, and
a byte-identity gate — the re-serialized bytes must equal the ORIGINAL file, so a reload that would
have produced a different artifact refuses to mint.

Purpose: make TRN-07's positive tier reachable from a fresh process without weakening APR-04.

Output: apr_reload.rs, the crate-internal run-from-parts constructor, tests.

Branch: `gsd/phase-4-apr-parity`. Wave 5, parallel with 04-06 (apr-cli only) and 04-12
(one aprender-train integration-test file). HARD CONSTRAINT: this plan touches ONLY the new
apr_reload.rs and mod.rs. If the parts needed to assemble a `SetFitRun<HeadFitted>` cannot be
constructed honestly from the artifact — a value that would have to be invented rather than
recovered — STOP and surface it as a finding rather than defaulting it.
</objective>
