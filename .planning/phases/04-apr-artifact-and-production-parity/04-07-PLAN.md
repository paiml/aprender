<objective>
Deliver the generic consumer surfaces (D-06: generic-only, no setfit-namespaced aliases): a NEW
`apr predict` command, the SetFit auto-detect branch in `apr inspect` (APR-05 recovery), and the
SetFit branch in `apr eval` that closes TRN-07's positive half.

**Review finding B4 is the substantive change.** The previous plan had validation and test
evaluation in one conceptual flow: the test command would create the lock, mint the token and grant
access. Codex found the contradiction — a separate `apr eval --split test` process has no lock
input, and creating the lock inside the test command defeats the requirement that the selection be
committed BEFORE test access. The workflow is now a durable artifact: validation evaluation writes
a lock file; test evaluation requires `--selection-lock`, reconstructs it, and lets the Phase 3
doors refuse an artifact or dataset that does not match. The library API that makes this possible
across two processes landed in 04-14 (`SelectionLock::from_canonical_bytes`) and 04-16
(`reload_verified_run_from_apr`) rather than being invented here.

Also closed here: M2 (the CLI input document, so multiline texts survive) and B5's consumer half
(all three commands read artifacts through `setfit_io::read_setfit_apr_file_bounded`).

Purpose: OPS-03 — generic commands auto-detect via the explicit tag and call the ONE shared core
path; OPS-02's inspect/eval/predict legs; APR-05 complete; TRN-07 "a user can reach the lock".

Output: predict.rs, inspect SetFit branch, eval SetFit branch + lock workflow tests.

Branch: `gsd/phase-4-apr-parity`. Wave 6, parallel with 04-08 (zero file overlap: 04-08 owns serve
files + apr-cli serve/handlers.rs + apr-cli Cargo.toml; this plan owns predict/inspect/eval +
enum/dispatch).
