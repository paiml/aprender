<objective>
Define the D-08 shared request/response pair ONCE in core and implement
`VerifiedSetFitModel::classify` — the single classification path every surface (Rust API, CLI,
HTTP) will serialize identically.

This revision fixes the two claims the cross-AI review found unenforceable:

**Review B6 — backend identity.** The previous plan reported trueno's runtime CPU feature
detection. Verified at plan time: `crates/aprender-core/src/setfit/` never calls trueno's backend
selection at all, and `trueno::Matrix::matmul` dispatches on SIZE (`matmul_naive` below the 64
threshold, `gemm_blis_parallel` above it, a GPU path when compiled in). Detecting that AVX2 is
AVAILABLE is therefore consistent with a scalar execution — reporting it would be exactly the
"label a run by intent" failure CLAUDE.md Verification Discipline rule 2 forbids. The identity now
travels back from the encode invocation and names the kernel entry point that ran.

**Review M1 — the non-finite claim.** The previous plan derived `Serialize + Deserialize` on a
struct with accessible fields, so a value could be built bypassing the validating constructor,
which made "non-finite values are unrepresentable" false. Fields become private with accessors and
`Deserialize` routes through the validating constructor.

Also closes M2 at the type layer: one shared `ClassifyRequestDocument` so the CLI `--input` file
and the HTTP body are byte-identical documents, which is what lets the parity harness send a text
containing a newline through all three surfaces unchanged.

Output: classify.rs (request + envelope + backend suite + classify + goldens + negatives), the
ExecutionBackend channel in encoder.rs/mod.rs.

Branch: `gsd/phase-4-apr-parity`. Wave 4, parallel with 04-05 (zero file overlap — this plan owns
core setfit files; 04-05 owns aprender-train files only).
</objective>
