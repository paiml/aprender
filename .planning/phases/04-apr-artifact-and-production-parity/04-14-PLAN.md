<objective>
Add the two public library doors the CLI plans need and today do not have. The cross-AI review
found both as HIGH findings: `apr setfit train` was planned to apply `--seed`/`--device` overrides
by deserializing into a **private** serde wire struct an external crate cannot name, and
`apr eval --split test` was planned to consume a selection lock that has **no reconstruction
path** — `SelectionLock::to_canonical_bytes` is public but nothing can read those bytes back.

Both are small, honest additions to aprender-train's public surface. Doing them here, in a
library-owned plan, is what keeps `apr-cli` a filesystem adapter (Ph2 D-04) instead of a crate that
reaches into another crate's internals.

Purpose: unblock 04-06 (config-file-first with overrides, D-07) and 04-07 (durable selection-lock
workflow, D-16/TRN-07) without either plan inventing library API inline.

Output: `SetFitTrainConfig::to_request`, `SelectionLock::from_canonical_bytes` with bounded parsing,
`ValidationEvaluation::from_wire`, tests.

**Review findings closed here:** the 04-06 private-wire-type HIGH finding, and the persistence half
of B4 (the CLI half lands in 04-07).

Branch: `gsd/phase-4-apr-parity`. Wave 2, parallel with 04-02 (aprender-core) and 04-13
(aprender-train bundle.rs/bundle_tests.rs/verify.rs). HARD CONSTRAINT: this plan touches ONLY
config.rs, lock.rs, lock_tests.rs and evaluate.rs. Do not touch bundle.rs, verify.rs or mod.rs —
parallel wave-2 and later plans own those.
</objective>
