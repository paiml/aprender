Extend `apr serve` with the SetFit surface (D-09/D-10): a feature-gated `setfit_model` AppState
slot in aprender-serve, a `POST /v1/classify` route taking core's request document and returning
core's envelope, readiness reporting the artifact hash + verified state, and startup auto-detection
in apr-cli's existing serve handler — no new serve command, no reimplemented model code in serve.

**Review findings closed here.** M4: the previous plan installed `/v1/classify` only when the model
slot was populated (Task 1) while Task 3 expected a 503 for a missing model — conditional
installation yields 404, so the two tasks contradicted each other. The route is now installed
whenever the feature is enabled and the handler owns the 503. M2/D-08: the request body is core's
`ClassifyRequestDocument`, so serve owns no schema at all. B5: startup reads the artifact through
the CLI's bounded door instead of `fs::read`.
