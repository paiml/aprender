CI-red fix, not future-proofing: `workspace-test` is a required X64 check, `feature_row` calls

### 2. [Rule 2 — missing critical assertion] The tracer compared component KEYS but not component VALUES

The plan's parts (a)–(d) assert the two roll-up keys exist and that `yhat`/`trend` match. But
`yhat` is built from `additive_terms` and **never reads** `extra_regressors_additive`, so a
roll-up that selected the wrong columns, or dropped the `y_scale` factor, would pass every
assertion the plan asked for. The oracle publishes all nine component series over the full
305-row grid, so part (d2) now compares them all. Justified retroactively: the `0..d.k`
mutation above is caught **only** by this assertion.

### 3. [Rule 1 — fixture format] Oracle scalars are one-element arrays

`retail_regressors_prophet140.json` stores `params.k`, `.m`, `.sigma_obs` as `[0.5029636]`
while the seven older fixtures store them bare, so `prophet::parity`'s `python_params` pattern
panics on this one. A local `scalar()` helper accepts both, which keeps the fixture
byte-identical to the spike original as the `cmp` verify requires.

### 4. [Rule 1 — repo convention] `serde_json::json!` trips the `unwrap` ban

`json!` expands to an internal `.unwrap()` for runtime values, which `.clippy.toml` bans
(GH-41). `types.rs` carries a file-level `allow` for this; `invariance.rs` does not, so five
sites were rewritten as explicit `serde_json::Value` construction. Also one
`clippy::range_plus_one`.

### 5. [FINDING — requires a decision] The prior-scale floor's stated mechanism is refuted, and the bound is far weaker than its prose claims

**This is the substantive finding of the plan and it should not be buried.**

The plan (inheriting a cross-AI review finding) justifies `regressor_prior_scale_min` thus:
`f64::MIN_POSITIVE` squares to exactly zero, the initial zero coefficients meet `0.0/0.0`, and
the result is *"a NaN that propagates through L-BFGS into every response field and serialises
as JSON null."*

**Measured, with the range check removed and `MIN_POSITIVE` put through the door, across 18
configurations spanning three series shapes (60-point ramp, 300-point ramp, 300-point {0,1}
indicator): no response field is ever non-finite.** `Model::objective` already carries
`if self.guard && !f.is_finite() { return 1e300 }`, which absorbs the 0/0 — the optimiser sees
a saturated constant, never a NaN.

The real failure is quieter and arguably worse: **L-BFGS runs ZERO iterations and
`extra_regressors_additive` is exactly `0.0` everywhere, while the door returns a
normal-looking forecast.** The regressor is silently ignored — precisely the D-21 class this
phase exists to prevent.

And the degenerate region is ~145 decades wider than the floor:

| `prior_scale` | iterations | `max abs extra_regressors_additive` |
|---|---|---|
| 1e-153 … 1e-9 | 0 | 0 |
| 1e-8 | 1 | 0 |
| 1e-7 | 257 | 6.9e-9 |
| 1e-3 | 595 | 1.99e-4 |
| 1e1 | 458 | 3.76e-1 |

Consistent across all three shapes. So the shipped floor of **1e-153 sits deep inside the
region where the fit collapses.**

**What I did, and deliberately did not do.** The plan's *acceptance criterion* — "at
`prior_scale = regressor_prior_scale_min` the fit returns a finite objective and finite
`beta`" — **does hold** (objective 2.13, beta finite). So the plan's own bar is met and I kept
the plan-specified constants. Moving `regressor_prior_scale_min` would change a published
contract constant that plan 06.1-03 is specified to build on; that is a human decision, the
same class as the wire-shape checkpoint. What I did instead:

- corrected the false rationale in **both** the contract comment and the Rust doc comment, so
  nothing in the tree records a mechanism that measurement refutes;
- added `forecast::tests::the_prior_scale_floor_is_a_representability_bound_not_a_usability_bound`,
  which asserts both halves (zero contribution at the floor; non-zero at 10.0) so the
  limitation is enforced rather than folklore.

**Recommended follow-up:** raise `regressor_prior_scale_min` to a measured usability floor
(~1e-7 on these measurements, rounded up a decade) as part of plan 06.1-03's measured-bounds
work, or accept the current floor knowingly. Note the review cycle fixed the *positive control*
for this check but left the *bound itself* inside the broken region — the same defect class,
one level up.
