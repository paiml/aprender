**The defect, MEASURED on this host during the 2026-09-21 review revision, not inferred.**
`~/.claude/settings.json:204` installs `rtk hook claude` as a `PreToolUse` hook on every Bash
call, and `rtk cargo test` is documented as "Test with failures-only output". Every `<verify>`
in this phase greps libtest's `test result: ok. N passed; 0 failed` line out of a log file. The
hook rewrites the command BEFORE it runs, so that line never reaches the log. The control pair,
run on a two-test throwaway crate through the live hook:

| form | log tail | verify exit |
|---|---|---|
| `cargo test --lib probe > log 2>&1; rc=$?; tail -12 log; test $rc -eq 0 && grep -E 'test result: ok\. ...' log` | `cargo test: 2 passed (1 suite, 0.00s)` — rtk's summary; libtest's line ABSENT | **1 — red on a green tree** |
| the same body inside the `r` runner below | `test result: ok. 2 passed; 0 failed; 0 ignored; ...` | **0** |

The rewrite surface is much wider than `cargo test`. Measured with `rtk rewrite`: `cargo
test`, `cargo build`, `cargo clippy`, `cargo fmt`, `git status`, `git diff`, `git show`, `git
worktree`, `grep`, `cat` (to `rtk read`), `ls`, `wc`, `tail` (to `rtk read --tail-lines`) and
`find` are ALL rewritten. Not rewritten: `cargo nextest`, `cargo run -p aprender-contracts-cli
--bin pv`, `git rev-parse`, `git check-ignore`, `cmp`, `sed`, `python3`. So a plan that greps a
count out of `grep -c`, proves a file did not change with `git diff --stat`, reads bytes out of
`git show`, or counts files with `ls`/`find` is measuring rtk's summariser, not the tree.

This is the same defect STATE.md records as a Phase 6 decision ("Every GSD verification command
in this repo must run through `rtk proxy`"), reaching every plan of this phase. It is settled
here so no executor has to re-derive it.

**The runner.** Every runnable verify body in all eight plans of this phase is wrapped in:

```
r() { if command -v rtk >/dev/null 2>&1; then rtk run "$(cat)"; else sh -c "$(cat)"; fi; }
r <<'SH'
<the body, verbatim, one statement per line or the existing one-liner>
SH
```

Measured properties of that form, each checked on this host:

- `rtk rewrite` returns EMPTY for it — the hook does not rewrite it.
- `rtk run` executes via `sh -c` with no filtering and propagates the exit status exactly
  (`exit 3` → `rc=3`).
- The `<<'SH'` body is quoted, so single quotes, `$`, backticks and regex backslashes inside it
  need no escaping, and a NESTED `python3 - <<'PY' … PY` works unchanged (verified).
- The `command -v rtk` guard means the identical text also runs on a host with no rtk, falling
  back to a bare `sh -c`, so a plan verify is not hostage to one developer's tooling.
- The heredoc terminator `SH` MUST sit at column 0. An indented `SH` does not close the
  heredoc and the command hangs waiting for input.

**Detector:** `assumption-delta scan 06.1` returned `detected: true`, one signal,
`kind: chosen` ("the chosen rule (or the refusal) actually fires"). Read against the phase
scope there is also a real `pluralization`: the Prophet design matrix has had exactly two
column families since it shipped (seasonalities, holidays) and gains a third (extra
regressors), and `HolidayArg` stops being prophet-only and becomes a two-arm argument.

**The noun that is now primary:** the design column family. Its identity model today is
`prophet::Column.holiday: Option<(usize, i64)>` — a two-valued discriminator where `None`
means seasonality and `Some` means holiday. Appending regressor columns makes `None`
ambiguous: it now means seasonality OR regressor.

**Decision: `add-alongside`, deliberately, with the debt named.**

Promoting `Column.holiday` to a three-valued `ColumnKind` is the textbook move and is refused
here for two measured reasons, not for convenience:

1. It contradicts this phase's governing frame and its evidence. Spike 011 measured the
   splice as a 219-line ADDITIVE change touching nothing under `crates/`. `Column` is a `pub`
   struct with `pub` fields; replacing the discriminator changes `feature_row`'s
   `c.holiday.is_some()` filter, `predict`'s holiday roll-up selector and every construction
   site — that is a rewrite of the thing CONTEXT.md says not to rewrite.
2. It directly threatens SC2. D-19's byte-identical gate is free precisely BECAUSE regressor
   columns append and no existing index moves. A discriminator change restructures the type
   the gate's own mechanism test compares field by field.

**How the ambiguity is prevented from biting — the invariant this checkpoint asks for, and it
is load-bearing rather than ceremonial.** The spike prototype identified regressor columns by
NAME membership, which is O(R) per column and silently wrong under a name collision: a
regressor literally named `yearly_delim_1` would be summed into `extra_regressors_additive`.
This plan replaces name membership with the STRUCTURAL fact the splice guarantees — regressors
occupy the contiguous trailing index range `base_k..k` where `base_k = d.k - regs.len()`. Plan
06.1-03 additionally refuses a regressor whose name collides with any generated column name,
so the component map keys stay unambiguous too.

**What would force a later promote:** a fourth column family, or any change that lets a
regressor column occupy a non-trailing index.
</assumption_delta_decision>
