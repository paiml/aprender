  <behavior>
    - Each of the eight cases run twice through `forecast::forecast` yields two equal signatures.

    - A response whose `fit_seconds` and `predict_seconds` are both replaced with different finite values has the SAME signature.

  <action>
Add part A to `invariance.rs` as `part_a_every_case_is_deterministic_through_the_door`.

For each of the eight recorded cases, call `forecast::forecast` twice and compare the two
signatures. Assert the number of cases exercised is exactly 8 and carry that count in the
assertion message: a determinism table that silently shrank would otherwise report green while
proving less. This is the same non-vacuity discipline the poisson sweep uses when it pins the
count of checked lambdas.

On a mismatch the message must be diagnostic rather than a bare inequality, and it must be
honest about what its diagnosis can and cannot establish. Report THREE things:

1. **The first divergent element, by index and by bit pattern.** Walk `yhat`, `yhat_lower`,
   `yhat_upper` and `trend` in the signature's own order, find the first index whose
   `to_bits()` differ, and print the field, the index, both values in `{:e}` form, both bit
   patterns in hex, and the absolute difference. A bare "signatures differ" on a cross-platform
   failure sends the reader back to the whole response; the first divergent bit sends them to
   the arithmetic. This matters most in CI, where the reader cannot re-run interactively.
2. **The whole-response max absolute difference**, per field, so a one-ULP libm difference
   reads differently from a structural break.
3. **The `budget_hit` note, stated as a POINTER, not as a subtraction.** Recompute both
   signatures with `diagnostics.lbfgs.budget_hit` masked to a fixed value and report whether
   masking it alone makes them equal. Say explicitly in the message what that result means and
   what it does not: `budget_hit` records whether the cooperative round-boundary budget in
   `fit::fit_prophet` (`fit.rs:104`, `:112`) was hit, and hitting it BREAKS THE OPTIMISATION
   LOOP — so when it flips, the parameters, the iteration count, the objective, the
   predictions and the bands all differ too. A masked-equal result therefore means "the ONLY
   difference is the flag, so the fits genuinely agreed"; a masked-still-unequal result does
   NOT mean "not an environment effect", because a real budget hit changes far more than the
   flag. Write both readings into the message. Masking is a triage pointer toward a loaded
   machine, never a proof that the difference is benign.

Do NOT remove `budget_hit` from the signature: SC2 puts `diagnostics` inside the comparison,
and carving one key out weakens the gate for the sake of a failure mode that has never been
observed. State that reasoning in the message itself.

**Scope note that belongs in the module rustdoc, because part A is arch-safe and one of this
module's tests is not.** Part A compares one host against ITSELF twice, and part B mutates a
response in memory — both are architecture-independent by construction and stay UNCONDITIONAL
on every runner. The cross-commit comparison against the committed baseline
(`every_baseline_case_reproduces_its_signature`, plan 06.1-01) is the one that is arch-keyed,
because `prophet::feature_row` calls `f64::sin`/`cos` through the platform libm and CI's
required `workspace-test` job runs on X64 Linux while the baseline is captured on aarch64
macOS. Say which test carries which exposure at the top of the module, so nobody later
"fixes" the CI red by relaxing part A or part B — the two parts that must never be conditional.

Add `the_signature_ignores_the_two_wall_clock_fields`: take one response, clone it, replace
`fit_seconds` and `predict_seconds` with different finite values, and assert the signature is
UNCHANGED. Without this, "we excluded the timings" is a claim about the code rather than a
property of the function — and a signature containing wall-clock is vacuous in the opposite
direction: always red, which is as useless as always green.

Keep the whole of part A inside `cargo test --lib` reach. Do not mark it `#[ignore]`: the
finding CONTEXT.md records is that the one harness watching an axis could only be reached with
an explicit flag.
  </action>

claimed by the field list and, without these mutations, tested by nothing.
