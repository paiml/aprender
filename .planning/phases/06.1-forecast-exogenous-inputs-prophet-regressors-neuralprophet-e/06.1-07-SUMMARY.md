# The `request_train_cost` guard regex — case table and observed results

The carried finding was confirmed by measurement, not suspected. `request_train_cost\([^)]*\)` stops at the FIRST `)`, so any call site with a nested parenthesised argument is truncated. The broken form lived in plan 06.1-05's verify body and 06.1-05's SUMMARY recorded it — so the defect was documented and the **class stayed open**, because nothing in the tree guarded it.

This plan ships the corrected instrument as a live test,
`forecast::tests::every_cost_call_site_is_found_whole_and_prices_what_it_should`, with the rule-7 case table below re-run on every invocation.

## MUST MATCH — and come back WHOLE

| Probe | Sites found | Top-level args |
|---|---|---|
| `let a = request_train_cost(&d, ds.len(), 0, 0, 0);` **(the nested-call shape)** | 1 | **5** |
| `request_train_cost(&d, p.points, p.n_lags, p.columns, 0)` | 1 | 5 |
| a MULTI-LINE call with one argument per line and a trailing comma | 1 | 5 |

## MUST NOT MATCH

| Probe | Result |
|---|---|
| `pub fn request_train_cost(d: &NpData, n_points: usize) -> u64 {` (the definition) | no sites |
| `log.train_cost` (a field access, no paren) | no sites |
| `let x = my_request_train_cost(1, 2);` (a longer identifier ending in the name) | no sites |

## The defect itself, pinned as an executable fact

```rust
assert_eq!(naive[0], "request_train_cost(&d, ds.len()", …)
```

on the input `let a = request_train_cost(&d, ds.len(), 0, 0, 0);`. If the naive form ever stops truncating, the balanced scan is no longer buying anything and the test says so instead of quietly agreeing.

Measured on the real file: **3 of the 5** `request_train_cost` call sites in `forecast.rs` at the wave base carried a nested call and came back as `request_train_cost(&d, ds.len()`.

## What the guard asserts that the compiler cannot

Arity is satisfied by any expression, so the compiler cannot say the door prices the REAL counts. The test does: exactly ONE `request_train_cost` call site exists in the shipped region of `forecast.rs`, and its 4th and 5th arguments are literally `n_event_cols` and `n_reg_cols`. Reverting the regressor argument to a literal `0` turns it red:

```
assertion `left == right` failed: the door must price the REAL regressor-column count —
a literal 0 here is the SC4 under-pricing this plan closed
  left: "0"
 right: "n_reg_cols"
```

The same balanced-paren scan was used to patch all 27 existing call sites when `R` was threaded through, rather than a `[^)]*` regex.

# The scoped no-interpolation guard — observed RED and the two-sided case table

`regressors::tests::no_shipped_regressor_path_interpolates_a_value`.

## Scope

All of `regressors.rs` above its test modules, plus **seven NAMED** regressor-carrying functions of `np.rs` (`training_samples`, `per_sample_regressor_width`, `train`, `add_regressors`, `predict_ts`, `predict_ar_1step`, `predict_ar_recursive`), with `//` line comments stripped so the detector reads CODE and not prose about interpolation.

## The exclusion, asserted POSITIVELY

`NpData::new` legitimately interpolates `y` over the imputed grid. The test makes three assertions rather than leaving the exclusion to inspection:

1. the expression `grid_y[k] = grid_y[a] + f * (grid_y[b] - grid_y[a]);` still EXISTS in `np.rs` — so the control has not gone stale;
2. the DETECTOR would catch it — so excluding it is a meaningful exclusion and not a statement about a string the detector ignores anyway;
3. the scope does NOT contain it.

Also asserted excluded: the probe's own fill rules (`grid_with_rule`, `GARBAGE`), which are TEST INPUTS by design. The scope could exclude test code structurally — both files carry their test modules at the end — so the plan's fallback (moving the probe's rule construction into a `#[cfg(test)]` module the scope skips by path) was not needed.

## The pattern's case table

MUST MATCH (4): `g[i] = g[a] + f * (g[b] - g[a]);` · `let v = lo + frac * (hi - lo);` · `out[k] = prev + t * (next - prev)` · `let y = lerp(a, b, t);`

MUST NOT MATCH (7): `let x = a + b * (c + d);` (no difference) · `acc += w * (x);` · `let term = d.scale * wj * x;` · `((v - st.mu) / st.std) as f32` · `10.0 + 0.01 * t + (2.0 * PI * t / 7.0).sin()` · `fn f(a: usize) -> Vec<f64> { Vec::new() }` (the `->` must not read as a difference) · `let n = (last - first + 1) as usize;`

## Decisions Made

- **`NpRegressors` has private fields and one fallible constructor.** The plan asked for a release-mode check instead of a `debug_assert!`; privacy makes it TOTAL rather than merely present, because `np.rs` cannot build the struct at all.
- **The mini-batch order shuffles SAMPLE POSITIONS, not grid indices.** One chunk element then addresses both the grid-length feature rows (`samples[pos]`) and the sample-length regressor rows (`pos`) with no second lookup table and no grid-shaped array. `rng.shuffle` draws a permutation of `n` either way, so the grid-index sequence is unchanged and the fit is bit-identical — evidenced by `invariance::` (9 tests) and the `np::parity` ladder (9 tests) staying green, not by the argument.
- **The `Spec` assembly moved above the dispatch.** Parts (a) and (b) of the regressor name-collision set are built from `prophet::columns(&spec)`, so a SHARED collision check needs the spec; rebuilding an equivalent at a second site would be two copies of one assembly rule. The cost is one `auto_seasonalities` call and one holiday-list clone on the neuralprophet arm, paid so a regressor name is refused by the SAME rule on both arms. The set is therefore a deliberate UNION rule rather than per arm — a name accepted on one arm and refused on the other would make D-22's one-shape claim unprovable in general.
- **No regressor diagnostics on the neuralprophet arm.** D-37 declines an identifiability diagnostic there, and adding a `diagnostics.regressors` block would contradict it. The regressor's effect is in `yhat`, which is not silent ignoring. `no_identifiability_is_computed_on_the_neuralprophet_arm` now asserts this against a SUCCESSFUL response carrying regressors — strictly stronger than the refusal it used to observe, which could not distinguish "not computed" from "not reached".
- **`metadata.version` bumped to 1.10.0 on this plan's own reasoning**, because `pv diff` supplied no suggestion (Deviation 5). A new published constant plus two new refusals on an arm that previously refused everything is additive → MINOR.
