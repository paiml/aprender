### The operand, and why it is not a second constant

```rust
let (design_rows, design_operand) = if model_name == "neuralprophet" {
    (span_days as usize, "span_days")
} else {
    (ds.len(), "points")
};
```

Prophet materialises one design row per SUPPLIED `ds` entry, so a gap costs nothing. The NP
event design is built over the imputed daily grid `np::NpData::new` lays across `first..=last`,
so its row count is `span_days` — always `>= len(ds)`, strictly greater on any gappy series.
Inheriting the prophet operand would under-price the gappy NP case by exactly `span / points`
(T-06.1-28). Both operands are bounded by 20 000 (`MAX_SPAN_DAYS` **is** `MAX_POINTS`), so the
product is `<= 2.365e7` either way and the no-overflow argument is unchanged.

The prophet message is byte-identical — `"points"` in the operand slot reproduces
`((points + horizon) x holiday_columns = (200 + 100) x 400)` exactly — and that is asserted,
not assumed, by `the_design_cost_refusal_names_the_operand_it_used_on_the_prophet_arm`.

### 3. [Rule 1 — plan premise measured FALSE] the reconciliation test could not pass a correct implementation

The plan words `the_event_components_reconcile_with_the_forecast` as "the sum of the per-event
components equals the difference between the events-ON and events-OFF forecasts". **That is not
true**, and the first run failed on it: roll-up 7.9257 against an ON−OFF difference of 6.3088,
a 0.202 relative miss on a component that is correct to 0.9 %.

Diagnosed by measurement rather than patched. `np::train` draws the event block from the same
`Rng` AFTER the model — so an events-OFF run initialises the model identically — but the
block's draws shift the subsequent **shuffle stream**, so the two fits are not the same fit.
Measured over the 32 event-free forecast rows: mean difference **−1.7864**, mean absolute
deviation **0.0703** (3.9 % of the shift). A LEVEL offset, not noise.

The test now measures that shift from the rows where the roll-up is exactly zero (where the
event term contributes nothing *by construction*), **asserts it is a level and not a shape
difference** so the single-number correction is justified rather than fudged, and then
reconciles to **0.0023–0.0212** against the 0.10 bar. A control asserts a roll-up left in
normalised units would FAIL the same comparison, so the case remains a units check. The
finding is recorded in `equations.event_training_determinism_bitwise`'s invariants.

### 4. [Rule 1 — verify defect] t2a's counting regex is order-sensitive
