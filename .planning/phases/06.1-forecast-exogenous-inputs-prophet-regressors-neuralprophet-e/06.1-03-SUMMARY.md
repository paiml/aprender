identifiability Gram plus its factorisation — and the second did not exist when Task 1
measured. So the sweep was run twice against the same five compositions.

to 3–4 ms** at R = 200 — a measured **0.2 % of the 2 s bar**. That is the evidence C-17's
`N*K^2 + K^3` term is bounded rather than asserted.

## The two findings routed to this plan

### Finding 1 — `regressor_prior_scale_min`: the hypothesis was refuted, so the floor did not move

The proposal was to raise the floor to a measured usability value of ~1e-7. **I ran that
campaign and it refuted itself.** Five series shapes, twelve decades, release build,
contribution relative to `yhat`:

| prior_scale | ramp60 | ramp300 | indicator300 | seasonal400 | bigscale200 |
|---|---|---|---|---|---|
| 1e-30 | 0 | 0 | 0 | 0 | 0 |
| 1e-10 | 1.1e-16 | 5.2e-14 | 3.5e-12 | 0 | 1.5e-11 |
| 1e-7 | 5.4e-9 | 1.6e-7 | 2.9e-8 | **2.8e-12** | 3.4e-8 |
| 1e-4 | 1.2e-3 | 8.2e-4 | 6.0e-6 | 2.0e-6 | 6.3e-5 |
| 1e-2 | 2.7e-3 | 8.2e-4 | 1.5e-5 | 4.6e-4 | 9.1e-5 |
| 1e0 | 2.6e-3 | 8.3e-4 | 1.4e-5 | 4.7e-4 | 9.3e-5 |

Two findings, both saying a floor is the wrong instrument:

1. **1e-7 is not a usability floor on every shape.** On `seasonal400` the contribution there
   is 2.8e-12 — as negligible as at 1e-9. A floor at 1e-7 would refuse requests that behave
   exactly like ones it accepts.
2. **There is no cliff to put a floor at.** The contribution decays continuously and
   saturates only between 1e-4 and 1e-2, and *where* it saturates is shape-dependent. That is
   not a degeneracy — `prior_scale` is a regularisation STRENGTH and shrinking the coefficient
   is what it is for. Any floor would refuse legitimate strong-regularisation requests on one
   shape while still admitting zero-contribution requests on another.

**Decision: the floor stays, and the D-21 silent-ignore class is closed at the OUTCOME.**
When a regressor's fitted coefficient is EXACTLY zero, the response says so in
`diagnostics.regressors[].warning`. The optimiser starts every coefficient at zero, so a
coefficient still exactly zero is one L-BFGS never moved — threshold-free, needing no contract
constant, and shape-independent by construction because it reports what the fit DID rather
than guessing from the knob. It also sidesteps the reversibility objection that stopped wave 1:
nothing that was accepted is now refused. Pinned by
`a_regressor_that_was_silently_ignored_says_so_identifiability` with a positive control at the
default prior scale, so the warning cannot fire on everything and say nothing.

### Finding 2 — the O(n·R²) component extraction: fixed, though it was not urgent, and the record says which

Measured first: under `MAX_REGRESSOR_DESIGN_COST` the quadratic term was already capped at
~5.6e6 float ops, and the stage-1 sweep measured `predict_s` at **0.000–0.016 s** at every
at-the-bound composition — under 1 % of the 2 s bar. The finding's 600 ms projection assumed
n = 3650 with R = 50, which is 182 500 cells and is now **refused**. So it could not have
misled the ceiling derivation.

It was fixed anyway, because Phase 7 re-prices these ceilings per tier: the quadratic is
unreachable at the shipped bound and reachable the moment the bound moves. Each distinct
component now carries the SPAN of columns that carry it, and `comp_of` takes that range.
Measured both directions with the ceiling raised so the geometry is reachable:

| composition | n | R | `predict_s` before → after |
|---|---|---|---|
| few_rows_many_regressors | 500 | 200 | 0.061 → **0.022** (2.8x) |
| balanced | 9 635 | 20 | 0.014 → 0.014 (unchanged) |
| many_rows_few_regressors | 19 635 | 4 | 0.013 → 0.013 (unchanged) |

The two low-R rows are the control: the fix touches the R-quadratic term and nothing else.

**Bit-identical, not merely equivalent.** The span is a SUPERSET and never a substitute for
the selector, so the accumulated terms, their order and the accumulator's initial `0.0` are
unchanged; the accumulator is deliberately kept rather than collapsed for the single-column
case, because `0.0 + (-0.0)` is `+0.0` while the bare product is `-0.0`. `predict_spans`
compares every emitted component against an unrestricted full scan by `to_bits()`, over a
design carrying all three column families and two holidays whose names are prefix-neighbours
(`alpha` / `alphabet`) so the name-sort cannot quietly interleave their columns.
**Observed RED** by mutating the span to `first..first + 1`: that turns the probe AND seven
`prophet::parity` predict-path tests red. The D-19 gate and the 24-column oracle tracer both
still pass.

### The degenerate-case policy, and the two corrections measurement forced

Both are recorded rather than silently made:

1. **A rank-deficient design reported `not_converged`** — the right problem under the wrong
   name, with per-column VIFs of ~1e15. The Cholesky already answers the question, so when the
   eigen loops exhaust, a smallest pivot at EPSILON of the largest now reports `singular`. It
   can only turn `not_converged` INTO `singular`, never the reverse.
2. **`regularized: true` co-occurs with `status: singular`** on a correlation matrix: the ridge
   fires only when there is no numerical rank left, while a merely ill-conditioned design
   factorises cleanly and gets a real, very large condition number. So the regularised-state
   test uses EXACT rank deficiency and its control is the CLEAN fixture, proving the ridge does
   not fire gratuitously.

Varying the input (CLAUDE.md rule 6) showed **which verdict a near-singular design gets is
decided by ROUNDING, not by how near-singular it is**: a ±1e-11 perturbation lands on `ok`
(condition number 2.25e7) while ±1e-6 on the same column lands on `singular` — the larger
perturbation gets the worse verdict. So no assertion is built on a near-singular input; the
degenerate tests use exact rank deficiency, which is deterministic, and a fourth test pins only
what IS invariant across all four shapes: the request succeeds, the status is one of the three
named states, nothing emitted is non-finite, and a withheld condition number always arrives
with a note saying why.

Every emitted number goes through one `finite_or_null` funnel, because `serde_json` renders a
non-finite f64 as the same `null` a deliberate one produces — the CR-03 defect class.

### 3. [Rule 1 — plan/reality contradiction] The plan's regularised-state test could not be written as specified

The plan asks for "a near-singular but Cholesky-recoverable matrix" driving
`regularized: true` with `status: ok`. On a correlation matrix that state is **unreachable** —
measured, not argued: a matrix that defeats an unridged Cholesky is ridge-dominated afterwards,
and one that does not is not ridged at all. The test now uses exact rank deficiency (which
measurably fires the ridge) and asserts the ridge's VALUE and warning text, with the clean
fixture as the control. Recorded in the test's own rustdoc.

### 4. [Rule 1 — latent defect] The sweep's composition builder produced an illegal geometry at high R

history points against `MIN_POINTS` = 10, and the door refused the composition. The always-run
geometry test exercises only the SHIPPED constants, so it could not have caught it. Fixed by
capping the horizon.
