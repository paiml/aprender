<selection_manifest_ownership>
## Where the selection manifests come from

The retired LoRA plan claimed to own generating the 40 selection manifests. That claim was already
stale when it was written. `scripts/run_bench_cells.sh` — shipped and lint-clean under 05-09 —
generates them itself in `generate_selections()`, one per (shots, seed), into
`$BENCH_DIR/selections/s{shots}-seed{seed}/selection-manifest.json`, via `apr data select` against
the attested dataset directory, and SKIPS any that already exist. The skip is deliberate and
documented in the script: regenerating a manifest is a NEW draw even at the same seed, so reuse is
what makes "one file" true rather than "two generators agreed".

So the capability survives the retirement untouched and this plan inherits it by invoking the
driver. Verify it rather than trusting this paragraph: read `generate_selections` and the
`selection=` path expression in `run_one_cell`, and confirm the two spellings agree — the 05-09
driver-gate test asserts exactly that, and it is in the suite this plan's verify runs.

The one manifest generated outside the driver is the pilot cell's, in Task 2, through the same
`apr data select` invocation copied verbatim from `generate_selections`. The sweep in Task 3 then
finds it present and skips it, which is the check that the two routes agree.
