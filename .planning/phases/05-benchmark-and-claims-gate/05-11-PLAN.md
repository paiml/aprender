## What this plan number used to be, and why it is not that any more

This plan was "lambda-vector checkpoint (A1) then the 40 LoRA GPU cells". It is retired by
`05-CONTEXT.md` D-19, recorded 2026-09-07 at this plan's own Task 1 checkpoint, before any compute
was spent. No LoRA cell was ever run. Two independent causes, either fatal alone:

- **(a) No GPU host.** `lambda-vector`/`gx10`, hardcoded by every `scripts/dispatch-*.sh`, is
  unreachable: 12 enumerated candidates, 12 failures, rc captured per attempt. The AWS fallback was
  enumerated and refuted rather than assumed — five instances, all stopped, none a GPU instance.
- **(b) The architecture is unimplemented — the decisive cause.** Qwen3.5-9B declares hybrid
  `layer_types` (24 linear + 8 full attention), `attn_output_gate`, and a multimodal
  `text_config`-nested checkpoint. `TransformerConfig` has no field for any of the three. The only
  hybrid-forward artifact sits in `aprender-contracts-staging`, which has no `Cargo.toml` and never
  compiles. Cause (b) is an inference from STRUCTURAL ABSENCE, not an observed loader failure
  (Verification Discipline rule 6); the cheap falsifier — point the loader at the real `config.json`
  — was named and NOT run.

**What is NOT retired.** The pairing MECHANISM is the whole point of keeping it: every SetFit cell
still records the selection-manifest hash that would bind a second method to an identical
sampled-ID set, so the arm can be added later without re-running the SetFit half
(`D-ITEM-05-15`). 05-06's `--selection-manifest` door, `run_classify_core`, `load_adapter`,
`predict_proba_tokenized` and the candidate-ledger single-candidate guarantee all remain shipped
code with shipped tests; what they lack is a real 9B checkpoint to be exercised against. 05-04's
paired-t machinery is likewise retained and contract-bound, unexercised by this phase's report.

**What does NOT get built.** `scripts/dispatch-bench-lora.sh` is not written. Nothing in this phase
may reference it.

**The selection manifests are not orphaned.** The retired plan claimed ownership of generating the
40 selection manifests. That claim was already stale: `scripts/run_bench_cells.sh` — shipped by
05-09 — generates them itself in `generate_selections()`, into
`$BENCH_DIR/selections/s{shots}-seed{seed}/selection-manifest.json`, skipping any that already
exist so that one file feeds every consumer. Measured, not assumed: read the function and the
`run_one_cell` path expression that consumes it. The capability therefore survives the retirement
untouched, and 05-12 inherits it by invoking the driver.
