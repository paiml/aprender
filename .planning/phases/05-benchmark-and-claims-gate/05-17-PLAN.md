**Where it lives, and why.** Add the recomputation to `bench_metrics.rs`, not to `bench_gate.rs`.
That module's header already says "This module computes NOTHING. It routes", and the recomputation
is exactly that: a router to the same surfaces `assemble_quality_block` uses. Putting a second
metric computation in the gate would give the phase two definitions of `f_avg`, which the gate's
own module header calls out as the failure mode ("a second mean is a second definition, and two
definitions of one number disagree eventually and invisibly"). Extend the header's surface table
with the new entry.

**The function.** `pub fn quality_from_confusion_matrix(confusion_matrix: &[Vec<u64>],
ordered_labels: &[String]) -> Result<RecomputedQuality, BenchMetricsError>`, where
`RecomputedQuality` carries `f_avg`, `macro_f1`, `mcc`, `per_class_precision`, `per_class_recall`,
`per_class_f1` and `n_rows: u64`. Implementation:

1. Validate shape first: `ordered_labels.len() >= 2`; the matrix is square; its dimension equals
   `ordered_labels.len()`; its counts total more than zero. Reuse the existing
   `BenchMetricsError` vocabulary where a variant fits (`TooFewLabels`, `EmptySplit`) and add
   ONE new variant for the shape disagreement, in the module's existing voice — every variant
   there is "a state in which SOME number could still be computed", and a non-square matrix is
   precisely that.
2. EXPAND the counts back into `(y_pred, y_true)` index vectors: for each `(true_i, pred_j)` cell,
   push `count` copies of `(j, i)`. This reconstructs the exact multiset of prediction pairs the
   matrix records. Document in the function why this is sound and not a reimplementation: every
   metric below is a function of the counts alone, all of them accumulate from integers, and the
   expansion feeds the SAME entry points `assemble_quality_block` called — so the recomputation is
   bit-identical by construction rather than by tolerance.
3. Route: `MultiClassMetrics::from_predictions_with_min_classes(&y_pred, &y_true,
   ordered_labels.len())` for the per-class vectors and `f1_avg(Average::Macro)`;
   `f1_average_for_classes(&metrics.f1, &OFFICIAL_F_AVG_CLASSES)` for `f_avg`;
   `f64::from(matthews_corrcoef(&y_pred, &y_true))` for MCC — the same `f64::from` widening of the
   same f32 return, because the row records the widened value. Author no arithmetic of your own.
