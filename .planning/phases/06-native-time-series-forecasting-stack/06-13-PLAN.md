The defect (crates/aprender-forecast/src/prophet.rs, the `Growth::Logistic` arm of `predict`'s
uncertainty block, around :790-810): per simulation row it computes
`lambda = s_cnt * (t_max - 1.0)` where `s_cnt = d.changepoints_t.len() as f64`, then draws
`n_changes` with Knuth's product method — `let l = (-lambda).exp();` then `loop { pp *= rng.uniform();
if pp <= l { break } n_changes += 1 }`. For lambda > 745.13, `l` is exactly 0.0 and the loop can only
end when `pp` underflows to zero, which happens after roughly 744 multiplications on average because
E[-ln U] = 1 and f64's smallest positive subnormal is near e^-744.

The RNG already available on the same `rng` value (crates/aprender-forecast/src/prophet.rs:626-650):
  - `pub fn uniform(&mut self) -> f64`
  - `pub fn normal(&mut self) -> f64`  (:642-646, Box-Muller from two uniforms)
  - `pub fn laplace(&mut self, b: f64) -> f64`
`normal()` is what a normal-approximation branch needs; nothing new has to be written.

The only logistic parity fixture is `wp_log_R_logistic_prophet140.json`. Its lambda must be measured,
not assumed — `lambda = n_changepoints_effective * (t_max - 1)`, and both factors come from the
fixture's own history length, changepoint count and forecast horizon.
