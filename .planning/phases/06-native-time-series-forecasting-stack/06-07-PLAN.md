## Cross-AI review dispositions carried by this plan (06-REVIEWS.md, `plans_commit: 88da44dcd`)

**REVIEW-06-01 — CONSEQUENCE (verified HIGH, resolved in 06-05).** This plan's prohibition list previously
said "never ship untransposed weight copies … only [in, out] copies live in memory (D-13)". That is false
of the `Bolt` this server loads and was restated: both layouts ship deliberately because `dot8` (D-14's
single-row kernel) needs contiguous `[out, in]` rows. The prohibition now forbids stripping them. The SC4
"< 30 MB" bar is unaffected — it measures the release binary carrying embedded f16 bytes, not residency.

**REVIEW-06-02 — CONSEQUENCE.** The server-side f32 parity test resolves its bar through the same
architecture-keyed pair 06-05 added and prints the bar name, the arch and the measured max|delta|.

**REVIEW-06-U4 — INCORPORATED (codex LOW; REFUTED on this host, guarded anyway).** Codex flagged that
Task 1's `timeout 60 cargo run …` assumes a `timeout(1)` that is not in the default macOS userland. On THIS
box it resolves to `/opt/homebrew/bin/timeout` (and `gtimeout` also exists), verified 2026-09-05 — so the
claim is false here. The verify still resolves the binary through `command -v timeout || command -v gtimeout`
and fails with an actionable install hint if neither exists, because a watchdog that silently is not there
turns a hung stdio child into an unbounded hang rather than a red check. That is a real hardening, not a
concession to the finding.
</review_dispositions>
