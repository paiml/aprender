**Why it matters for 0.71.** V1 (TTFT ≤ 2× llama.cpp) and V2 (load + TTFT beside pp512/tg128) need a
baseline series, and the DoR ledger lists `baseline` as missing for the V1/V2/V6 rows. The nightly row
is that series. It also feeds OBS-06 RED rules, the OBS-07 tag baseline and OBS-09c (one traced request a night).

**Layering. This extends #4551; it does not duplicate it.**
- `apr-raw-samples-v1` (on `la-71/4551-raw-samples`) is the subject's per-arm document: raw iterations, no statistics.
- `apr-perf-ledger-v1` is the recorder's row:
  - two arms, each referencing its raw-samples document by sha256
  - the statistics derived from those samples
  - the same-run ratio, which must equal the quotient of the medians (an asserted ratio is RED)
