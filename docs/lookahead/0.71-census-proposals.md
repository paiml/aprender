# 0.71 census: three proposed pv changes (#4709)

These are proposals only. Each one says where the code is, what changes,
and the test that would prove it. The census step branch does not need
any of them to reach 153 bound; they decide whether that 153 means what
it says.

## P-1. Name a contract by its path, not its stem

**Where.** `crates/aprender-contracts/src/ontology/extract/pv_contract.rs`,
`extract_one`: `let s = iri("contract", stem);`. `documents()` already
computes `rel`, the path from the repository root, and emits it as
`ont:file`.

**Problem.** 24 stems have a file in two directories (for example
`contracts/http-api-v1.yaml` and `contracts/aprender/http-api-v1.yaml`).
Both files become one graph node with two `ont:file` values, so a symbol's
`sym:implements` cannot say which file it implements. Step 4 had to pick
the twin from the binding file's directory instead of from the graph.
The `duplicate-stems` lint baselines 48 divergent stems for the same
reason.

**Change.** Key the IRI by `rel` with `.yaml` removed
(`contract/aprender/http-api-v1`), keep `ont:id` as the stem, and resolve
a binding row's `contract:` against the binding file's own directory
first, then the top level.

**Test.** A fixture with `a/x-v1.yaml` and `b/x-v1.yaml`, where only
`a/binding.yaml` binds `x-v1`: the graph has two contract nodes, and only
`contract/a/x-v1` has a `sym:implements` edge. RED today (one node).

**Cost.** Every contract IRI in `contracts.nt` changes, so it is a
whole-file regeneration, and every SHACL shape and query that builds a
`contract/<stem>` IRI moves with it. It should be its own PR, not part of
the census step.

## P-2. Census skips `kaizen/` by name

**Where.** `crates/aprender-contracts/src/lint/gates.rs`,
`collect_yaml_files`: the walker skips any directory named `kaizen`,
`legacy`, `pipelines`, `publish-manifests` or `quarantine`. Census and
`pv extract` both use this walker.

**Measured.** 46 files are skipped: 39 in `contracts/entrenar/kaizen/`
and 7 in `contracts/trueno/kaizen/`. All 46 pass `pv validate`, and each
has `metadata.kind: kaizen`. The skip arrived with the monorepo merge
(21d8c4d8b4, 2026-04-06), and its comment gives a reason for
`publish-manifests` and `quarantine` only. The earlier note in this
directory that census "does not walk depth 3" was wrong: the walker
recurses to any depth and skips these directories by name.

**Change.** Pick one of two:

- (a) Walk `kaizen/`. n rises by 46, almost all of them unbound. The
  release step stays `min(100, unbound)`, so the 0.71 bar does not move.
- (b) Keep the skip, and have census report the skipped files in a
  `skipped_by_name` count beside `quarantined_n`, so the total is visible.

(b) is the smaller change. (a) is what the census claims to count.

**Test.** (a): a `kaizen/x-v1.yaml` fixture is counted. (b): it shows up
in `skipped_by_name`, and n is unchanged.

## P-3. Count only refs that resolve

**Where.** `pv_contract.rs`, `extract_one`: `entity.ref` is copied into
`ont:entityRef` as a literal string. Census counts any `entity:` with a
`type` and a `ref` as an instance.

**Problem.** A ref to a symbol that does not exist counts as bound. Every
ref on the census step branch was chosen from symbols that have
`sym:resolved true` in `contracts.nt`, but nothing enforces that, so the
ratchet can be met with ghost refs.

**Change.** For `type: code`, census looks the ref up among the graph's
resolved symbols. A ref that does not resolve goes into a new
`instance_unresolved` bucket, which does not count as bound.

**Test.** A planted fixture with `ref: no::such::symbol` lands in
`instance_unresolved`, and bound does not change. On the census step
branch the bucket should be 0, which checks steps 1 to 4.
