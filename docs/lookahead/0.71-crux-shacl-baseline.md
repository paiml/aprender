**The 6 extra results.** A throwaway patch printed the oracle's full multiset
difference. It was never committed, and the worktree was restored clean. The
difference is 6 ORACLE-ONLY and 0 PV-ONLY, all with component `closed`. Each is an
rdf:type value on a focus node of a `sh:closed true` shape whose
`sh:ignoredProperties` does not list rdf:type. Focus IRIs below are under
`https://ont.paiml.dev/v1alpha1/`.

| Closed shape (`sh:closed true` at `shapes.ttl` line) | `sh:ignoredProperties` | ORACLE-ONLY focus nodes |
|---|---|---|
| `claude-md` (1249) | none | `llm/claude-md` |
| `csv-train` (1288) | none | `csv/csv-train` |
| `model-setfit-slice` (1479) | `model/file`, `model/contract` | `model/4a75ee8031b3…4057e`, twice: it has two types, `AprModel` and `Model` |
| `parity-receipt-complete` (1720) | none | none at this commit |
| `readme-root` (1826) | none | `readme/readme-root` |
| `refusal-receipt-v1` (1857) | none | `refusal/refusal-receipt-v1.refusals.0` |

**Cause.** pv admits rdf:type on every closed shape. `check_closed`
(`crates/aprender-contracts/src/ontology/shapes.rs:864`) chains `RDF_TYPE` into the
allowed predicates at line 875. SHACL Core allows only the shape's own paths and
its `sh:ignoredProperties`. W3C `node/closed-001` tests exactly this.

**So `make oracle-check` is RED** (step E).
- The Makefile is `.ONESHELL` without `-e`, and the oracle runs last, so
  `make oracle` fails with the oracle's status. `oracle-check` stops there, before
  its `git diff --exit-code`, and the stale record would fail that too.
- Only `scripts/release/ont10_readiness.sh` runs `oracle-check`. No workflow, PR
  check or other Makefile target does.

The fix that serves row 8 is the precondition in §14.6: pv drops the implicit
rdf:type, the 6 closed shapes declare it in the same PR, and `node/closed-001` is
vendored.
