# 0.71 census P-3: a code ref is bound only when it resolves (#4709)

`0.71-census-p3.patch` changes `pv census`
(`crates/aprender-contracts-cli/src/commands/census.rs`). It applies to
main at the merge-base of this branch. It is a patch file, not a commit,
because this host builds nothing; the tests run on the test host.

## What changes

`entity.ref` is a literal to `pv extract`, so before this change a
`{ type: code, ref: no::such::symbol }` counted as bound. Now census reads
the committed graph next to the corpus (`contracts/contracts.nt`) and
collects every symbol with `sym:resolved true`. A `type: code` instance
whose ref is not in that set:

- is counted `unanchored`, so it is not bound and the ratchet's
  class + instance falls;
- adds nothing to `by_entity_type`;
- is listed by path in a new top-level `instance_unresolved` field, and
  in the table output.

`by_anchoring` keeps its three keys and its sum, so
`scripts/check_census_derived.sh` needs no change. Only `type: code` is
judged; other entity types (`binary`, `gguf`, ...) name files, not
symbols, and are counted as before.

With no readable `contracts.nt`, the set is empty, so every `type: code`
ref is unresolved. A missing graph can lower the bound count, never
raise it.

## Measured effect (shell over the trees; not yet the patched binary)

| Tree | code refs | unresolved | bound before | bound after |
|---|---|---|---|---|
| origin/main | 0 | 0 | 48 | 48 |
| la-71/census-071-step, committed `contracts.nt` | 105 | 14 | 153 | 139 |
| la-71/census-071-step + its regenerated graph patch | 105 | 0 | 153 | 153 |

The middle row matters. The census step branch carries its regenerated
graph only as `0.71-census-step-contracts-nt.patch`. The 14 refs are the
type-qualified methods of step 2, which resolve only in the regenerated
graph. Once this patch lands, the census step needs its regenerated
`contracts.nt` committed in the same PR, or its count falls to 139, below
the 0.71 bar of 148. That is the check working: a stale graph proves less.

## Tests in the patch

- `a_code_ref_is_bound_only_when_the_graph_resolves_it`: three code refs,
  one resolved, one absent from the graph, and one with
  `sym:resolved false`. Bound 1, unresolved 2, `by_entity_type.code` 1,
  and the anchoring sum equals `n_parsed`.
- `without_a_graph_every_code_ref_is_unresolved`: fail closed.
- `a_ref_of_another_entity_type_is_not_judged_by_the_graph`.
- `render_json_is_deterministic_and_ends_in_one_newline` now also requires
  the `instance_unresolved` key.

To run them, on the test host:

    git apply docs/lookahead/0.71-census-p3.patch
    cargo test -p aprender-contracts-cli --lib census

The RED proof: revert the `tally` hunk alone, and the first two new tests
must fail.
