# 0.71 census P-1: a contract is keyed by its path (#4709)

`0.71-census-p1.patch` changes `pv extract`
(`crates/aprender-contracts/src/ontology/extract/`: `pv_contract.rs`,
`code.rs`, `lean.rs`, `gguf.rs`, `apr_model.rs`). It applies to main at
the merge-base of this branch. It is a patch file, not a commit, because
this host builds nothing; the tests run on the test host.

## Problem

A contract's graph node was `contract/<stem>`. On main, 1894 contract
files make 1829 nodes: 55 stems have a file in two or more directories,
and each set shares one node with several `ont:file` values. No edge can
say which file it means. The census step had to pick a twin from the
binding file's directory outside the graph.

## Change

- The subject is `contract/<key>`, where the key is the path under
  `contracts/` without `.yaml`. A top-level contract's key is its stem,
  so its IRI does not move. A subdirectory contract moves, for example to
  `contract/aprender%2Fhttp-api-v1` (`iri` escapes the `/`). `ont:id` is
  still the stem.
- `lean:modelOf`, `model:contract` (gguf rungs and files, apr models)
  point at the key of the contract being read.
- A citation by stem alone (a `relations:` target, a binding row's
  `contract:`) goes through `ContractIndex::resolve`. The order is: the
  stem's only file; else its file in the citing file's directory; else
  its top-level file; else the bare stem, which dangles visibly and never
  picks a twin by byte order.
- A target that starts `./` or `../` is relative to the citing file's
  directory. On main, 9 `sym:implements` edges name `contract/..%2F<x>`,
  a node no file has, because binding rows in subdirectory registries
  write `contract: ../x-v1.yaml`. These now resolve.
- `code::Resolution` gains `origins`, the registry file of each symbol,
  so `extract` can resolve each row from its registry's directory.
  `Bound.contract` keeps the stem, so the bindings and shapes gates that
  read `resolve_all` see no change.

## Tests in the patch

- `a_contract_key_is_its_path_under_the_contract_dir`: a key table.
- `a_stem_resolves_to_its_local_then_top_level_file_and_never_by_byte_order`:
  14 cases, including a twin with no local or top-level file (dangles), a
  path, `./` and `../`, and a `../` that climbs out (as written).
- `twins_are_two_nodes_and_a_stem_relation_names_the_local_one`: two
  `x-v1` twins become two nodes with one `ont:file` each, `ont:id` stays
  the stem, and `a/y-v1`'s `depends_on: [x-v1]` names `a/x-v1`. This is
  RED on main, where there are three nodes.
- `a_binding_row_implements_the_twin_in_its_own_directory` (`code.rs`):
  a row in `a/binding.yaml` naming `x-v1` implements `a/x-v1`, and a row
  naming `../t-v1.yaml` implements the top-level `t-v1`.

To run them, on the test host:

    git apply docs/lookahead/0.71-census-p1.patch
    cargo test -p aprender-contracts --lib ontology::extract

The RED proof: replace `iri("contract", &key)` with
`iri("contract", stem)` in `extract_in`. The twin and binding tests must
fail.
