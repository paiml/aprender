## Three falsifiers git does not report
1. **FALSIFY-KREG-009 needs PR-A underneath.**
   - Pick 16 commits the `cpu.repeat_penalty.f32` op receipt, whose `build_identity` is `d64d8a7118`. That commit already contains `ee32767fef`, so its `apply_repeat_penalty` penalises a token once, however often the token occurs in the window.
   - The harness `run_repeat_penalty` (`kernel_registry_op_parity.rs` L362) plants one token twice in the window (L372–373). Its oracle penalises that token once (`formula`, L579: "once per distinct t<n in last_n").
   - main's `apply_repeat_penalty` walks every token in the window (`generate_quantized.rs` L164 on main: `for &token in &recent_tokens[start..] {`), so it compounds per occurrence. That is the defect `ee32767fef`/`0f4219ad47` fixes.
   - So on B2 without PR-A, `committed_op_parity_receipts_hold_on_this_host` (L756) is forecast RED, and the receipt goes stale too (falsifier 3).
   - B3 therefore sits on PR-A. It does not carry `ee32767fef` itself, because a fold is a move.
