# PR-REVIEW-SKILL-002 — grounded adversarial PR review with a signed receipt

**Status:** SPEC for implementation
**Supersedes:** PR-REVIEW-SKILL-001 (draft, 2026-08-30)
**Complements:** `dogfood.sh`, `nightly-ux-crux`, the `check_*.sh` guards in `ci.yml`, `pmat comply check`
**Workflow:** `pmat work add` → branch → PR → `ci / gate`. Contract ships in the same PR as the implementation.

## §0 What changed from v1, and why

Two inputs drove v2: external prior-art research, and the SGCR/attestation research memo. Not all of it survives contact with this repo's constraints. The rejections are as load-bearing as the adoptions.

| # | Change | Rationale | Source |
|---|---|---|---|
| A1 | Findings serialize as **SARIF 2.1.0**, not bespoke JSON | SARIF already encodes the exact "ran and found nothing" vs "could not run" distinction v1 §2.0 was inventing (`invocations[].executionSuccessful` + `toolExecutionNotifications`). Renders in GitHub code scanning for free. | research §C |
| A2 | Consultation record serializes as an **in-toto Statement v1** in a DSSE envelope | Standard container for "this process ran over this subject". Validated by `check-jsonschema`, not by hand-rolled `jq`. | memo; research §C |
| A3 | **Diff boundary is `git merge-base`**, never `origin/main` | Kills v1 §8.1 half-dead. A floating base pulls in other agents' commits, inflates tokens, and manufactures false positives. | memo |
| A4 | **Index staleness is recorded and gating**, not hoped away | The "66 commits behind" scar. `index_commit` is stamped into the receipt; if it is not an ancestor of `HEAD`, verdict is `DEGRADED`. | memo; research §J |
| A5 | **Reviewer actor ≠ author actor** | Self-review is worth close to nothing: intrinsic self-correction degrades reasoning (Huang et al., ICLR'24), models self-prefer, and a same-model critic yields ≈0 gain. A separate grounded critic is the first configuration that beats single-agent. | research §D |
| A6 | **Two-tier blocking**, not advisory-only | Infer at Facebook: same analysis, same FP rate, fix rate went from ≈0 (batch/advisory) to >70% (diff-time, in-workflow). Advisory-only findings get ignored. v1's fear of routed-around gates is also real — hence *narrow* blocking, not broad. | research §E |
| A7 | **Precision budget is a measured, ratcheted number** | Google Tricorder: review-time analyzers must hold ≤10% effective false positives or they get disabled. A category above the bar is auto-demoted to advisory. | research §A/E |
| A8 | **Comparative perf claims carry the comparator's command + env + artifact hash** | MLPerf rule: unverified results must be labelled unverified. This is the `2.93× Ollama` scar with a standards answer. | research §I |
| A9 | Mutation testing is the **falsification gate for the guard**, and diff-scoped elsewhere | v1's "construct a failure" was qualitative. `cargo mutants --in-diff` makes it a number. But see R3. | memo |

**Rejected from the memo, with reasons:**

| # | Rejected | Why |
|---|---|---|
| R1 | SLSA **Build L3** claim | L3 requires provenance generated by an isolated builder the tenant cannot influence. A skill invoked by the same agent that wrote the code is **self-attestation ≈ L1**. Claiming L3 is exactly the enforcement theater this repo names as its dominant failure mode. The receipt declares `"attestation_level": "L1-self"`. |
| R2 | **Fulcio / Rekor** public transparency log | External SaaS in the verification path. Violates the sovereign constraint. Sign with a repo-local key (`minisign`/`age` keypair in CI secrets); the transparency log is `evidence/pr-review/` under git, which is append-only by review policy. |
| R3 | "Any surviving mutant **blocks** the merge" | `cargo-mutants` across 82 crates is minutes-to-hours. Unbounded mutation on every PR is a gate whose failure mode is to stop the line for cost, not defect. Mutation blocks only on **guard/gate-script diffs** (§6); elsewhere it is budgeted and advisory. |
| R4 | Predicate type `slsa.dev/verification_summary/v1` | VSA has a fixed schema (`verifier`, `policy`, `verificationResult`, `verifiedLevels`). Review payload does not fit it. Use a custom predicate type. |
| R5 | DORA throughput/stability figures as load-bearing | Fine as motivation, not as a threshold source. No threshold in this spec derives from them. |
| R6 | Full SCIP/LIP live-intelligence layer as a v2 requirement | Real upgrade, wrong phase. `pmat query` + `index_commit` recording closes the actual defect now. SCIP via `rust-analyzer scip .` is a Phase 3 pick (§9). |

## §1 The grounding rule

Every claim the review makes about external reality is exactly one of:

| mark | means | required evidence in receipt |
|---|---|---|
| `cited` | traced to a consultation this run performed | `query`, `source_uri`, `excerpt_sha256`, `excerpt` (≤400 chars) |
| `measured` | produced by a command this run executed | `command` (argv array), `exit_code`, `stdout_sha256` |
| `asserted` | reviewer judgement | `rationale`; permitted, visibly distinct, never blocking |

There is no fourth category. An unmarked claim is a **defect in the review**, and the guard rejects the receipt.

**§1.1 `cited` is verified, not just labelled.** A recorded excerpt that does not support its claim is the same failure as no excerpt. The guard requires `excerpt_sha256` to match `sha256(excerpt)` and requires `excerpt` to be non-empty. Semantic entailment checking is Phase 3 — until then, an unsupported-but-well-formed citation is a known residual risk, stated here rather than hidden.

**§1.2 Contradiction is fatal to the claim, not to the run.** An `asserted` claim that contradicts a `measured` value in the same receipt is dropped and logged as `finding.suppressed_by_measurement`. This is the anti-hallucination-snowball rule.

## §2 Diff boundary

```bash
BASE=$(git merge-base origin/main HEAD)
git diff "$BASE"..HEAD          # the only diff the reviewer sees
```

`BASE` is recorded as `base_sha`. `HEAD` as `head_sha`. Any consultation answering about code outside `git diff --name-only "$BASE"..HEAD` must say so.

**Baseline cache reuse** (complexity, TDG, semantic index) is admissible only when:

```bash
git merge-base --is-ancestor "$baseline_commit" HEAD   # exit 0 required
```

and the file's last modification is at or before `$baseline_commit`. Otherwise recompute. Cache hits are recorded as `cache_hits: N` — an uncounted cache is an unfalsifiable one.

**Blast radius.** On a monorepo diff, consultations run over the changed crates plus their reverse dependencies:

```bash
cargo metadata --format-version 1 | jq -r '...'   # or: pmat analyze reachability -p .
```

Recorded as `affected_crates[]`. A consultation that skipped a crate in `affected_crates` is `DEGRADED`, not silent.

## §3 The consultations

Four. Each has a trigger, a required output, and an unavailability behaviour.

### §3.0 Unavailability is never silently green

Encoded in SARIF, not prose:

| state | SARIF encoding | verdict effect |
|---|---|---|
| consulted, found nothing | `executionSuccessful: true`, empty `results`, empty `toolExecutionNotifications` | none |
| consulted, found something | `executionSuccessful: true`, populated `results` | `FINDINGS` |
| could not consult | `executionSuccessful: false` + `error`-level `toolExecutionNotifications` | `DEGRADED` |
| not triggered | run object omitted; `consultations.<k>.status: not-triggered` with `trigger_reason` | none |

It must not be possible to distinguish these by reading prose. It must be trivial to distinguish them by reading the artifact. `pmat` MCP being `ConnectionRefused` exercises row 3 on day one — that is the intended behaviour, not a bug in the rollout.

### §3.A `pmat` — quality and duplication (**every PR**)

Trigger: unconditional. Required output:

- `complexity_delta[]` — per changed function, **increase only**, token-walk scoring (line-scan penalizes formatters; do not use it)
- `tdg_delta[]` — per changed file, A+…F
- `satd_introduced[]` — markers added **by this diff**
- `duplication_hits[]` — `pmat query` for an existing implementation of what the diff adds. PERF-055 nearly re-implemented ~7,200 lines across 46 files that already existed. This is the highest-EV field in the receipt.
- `index_commit` — the SHA `.pmat/context.db` was built from

Preconditions, both non-negotiable:

```bash
pmat query "x" >/dev/null        # builds .pmat/context.db; without it CB-200 is Skip, not Pass
git merge-base --is-ancestor "$index_commit" HEAD || echo "DEGRADED: stale index"
```

An unmeasured CB-200 is `Skip`, and **`Skip` is not a pass** — it is `DEGRADED`.

### §3.B NVIDIA CUDA documentation (triggered)

Trigger: any changed path matching `crates/aprender-gpu/**`, `crates/aprender-serve/src/cuda/**`, `*cuda*`, `*ptx*`, `*cublas*`, `*fp8*`, `*nvrtc*`; or PR body/commit messages matching `sm_\d+`, `cu[A-Z]\w+`, `cuda[A-Z]\w+`, or a GPU architecture name.

Required output: for every device-behaviour claim, either a `cited` entry (query + excerpt) or an explicit `no-authority-found` entry naming the query that returned nothing. The second form is mandatory — without it, "the docs said nothing" is indistinguishable from "I did not ask."

This is the consultation with the most evidence of being needed: the 18% regression shipped on an ungrounded stream-ordering claim, #2765 (16-row alignment), #2789 (E4M3), #2771 (PTX aliasing), #2786 (GB10 Blackwell) were all CUDA questions asked of memory while the docs server sat idle.

### §3.C CRUX — user-facing surface and competitive claims (triggered)

Trigger: the diff changes a CLI subcommand or flag, an HTTP route, an MCP tool, a config key, or an output format.

Required output per surface:

- covering CRUX contracts (`contracts/crux-*.yaml`, matched on `category` + surface — **not** full semantic search over all 275; that is §8.2 resolved as (a))
- competitor behaviour per contract's `competitor:` field
- `gap_effect: closes | widens | none`
- `crux_coverage: none` where no contract covers the surface — **that is itself a finding**

**§3.C.1 Comparative performance claims (the `2.93× Ollama` rule).** Any claim of the form "N× *competitor*" in the diff, PR body, docs, or benchmark output must carry:

```yaml
comparator:
  command: ["ollama", "run", "...", "--..."]     # argv, exact
  version: "ollama 0.x.y"                         # captured, not remembered
  env_sha256: "..."                               # hash of the recorded environment block
  artifact_sha256: "..."                          # the model/binary actually exercised
  log_path: "evidence/bench/<run-id>/comparator.log"
```

Absent any field, the claim is reclassified `asserted`, marked `unverified_comparative_claim`, and — per §7 — **blocks**. The book published *"2.93× Ollama"* from a harness that never ran Ollama; this is the gate that makes that impossible rather than merely discouraged.

### §3.D Mutation — adversarial falsification (scoped)

Replaces v1's qualitative `adversarial_cases`.

| diff shape | mutation requirement | blocking |
|---|---|---|
| touches `scripts/check_*.sh`, `dogfood.sh`, `ci.yml` gate logic, or a `contracts/*.yaml` falsifier | 100% kill on the committed mutation set for that guard | **yes** |
| touches Rust source | `cargo mutants --in-diff <diff> --timeout 120 --jobs 4`, capped at `MUTANT_BUDGET=40` | advisory |
| docs / non-code | not triggered | — |

Bash guards are exercised with `bats-core` fixtures (TAP output, `setup`/`teardown` isolation, mockable externals) — see §6.

Surviving mutants are recorded with `mutant`, `file`, `line`, `killed: false`. A run that reports zero mutants attempted is `DEGRADED`, not clean: a mutation set that matches nothing passes vacuously, which is the same shape as `pv lint <FILE>` returning PASS over zero contracts.

## §4 The receipt

Two artifacts per review, both under `evidence/pr-review/<pr>/<head_sha>/`:

```
receipt.intoto.jsonl     # DSSE-wrapped in-toto Statement v1 — the consultation record
findings.sarif           # SARIF 2.1.0 — the findings, one run per consultation
```

### §4.1 in-toto Statement

```json
{
  "_type": "https://in-toto.io/Statement/v1",
  "subject": [
    { "name": "git+https://github.com/paiml/aprender",
      "digest": { "sha1": "<head_sha>" } }
  ],
  "predicateType": "https://paiml.dev/attestations/pr-review/v2",
  "predicate": {
    "skill_version": "2.0.0",
    "attestation_level": "L1-self",
    "pr": 2783,
    "base_sha": "<merge-base>",
    "head_sha": "<head>",
    "author_actor":   { "kind": "agent|human", "id": "..." },
    "reviewer_actor": { "kind": "agent|human", "id": "..." },
    "affected_crates": ["aprender-gpu", "aprender-serve"],
    "verdict": "PASS|FINDINGS|DEGRADED|BLOCK",
    "consultations": {
      "pmat": { "status": "consulted|not-triggered|unreachable",
                "index_commit": "...", "index_is_ancestor": true,
                "complexity_delta": [], "tdg_delta": [],
                "satd_introduced": [], "duplication_hits": [] },
      "cuda": { "status": "...", "trigger_reason": "...",
                "queries": [ { "q": "...", "excerpt_sha256": "...",
                               "result": "found|no-authority-found" } ] },
      "crux": { "status": "...", "surfaces": [], "contracts": ["CRUX-A-08"],
                "gap_effect": "closes|widens|none", "crux_coverage": "covered|none",
                "comparative_claims": [] },
      "mutation": { "status": "...", "scope": "guard|in-diff|not-triggered",
                    "attempted": 37, "killed": 37, "survivors": [] }
    },
    "findings_ref": { "path": "findings.sarif", "sha256": "..." },
    "cost": { "input_tokens": 0, "output_tokens": 0, "wall_seconds": 0 }
  }
}
```

`attempted: 0` with `status: consulted` is rejected by the guard. So is `reviewer_actor == author_actor` (§5).

### §4.2 SARIF

One `runs[]` entry per consultation, `tool.driver.name` ∈ {`pmat`, `nvidia-cuda-docs`, `crux`, `cargo-mutants`}. Each `result` carries in `properties`:

```json
{ "grounding": "cited|measured|asserted",
  "source": "...", "failure_scenario": "...",
  "precision_class": "blocking|advisory" }
```

`failure_scenario` is required and non-empty on every result. A finding that cannot name the concrete failure it permits is not a finding — it is a comment, and comments are not what this skill is for.

### §4.3 Signing

```bash
# generated in CI, verified in CI. No external transparency log.
minisign -S -s "$PR_REVIEW_SIGNING_KEY" -m receipt.intoto.jsonl
```

Verified by the guard against the committed public key at `.github/pr-review.pub`. The signature proves the receipt came from the CI environment, not that the review was honest. **State this in the PR comment.** Cryptographic assurance of provenance is not assurance of diligence, and conflating them would be the most sophisticated form of theater this repo has yet produced.

## §5 Author / reviewer separation

The review is a **separate invocation** from the authoring session: fresh context, adversarial system prompt, no access to the author's reasoning trace.

| control | rule | guard check |
|---|---|---|
| distinct actor | `reviewer_actor.id != author_actor.id` | RED if equal |
| grounded findings | ≥1 `measured` or `cited` finding on any PR >200 changed lines | RED if all `asserted` |
| independent audit | 10% of receipts re-reviewed by a second invocation, results in `evidence/pr-review/audit/` | sampled offline |

Audit divergence is the instrument for §8's ratchet: **measure first, then set the threshold.** Initial recording only; no target until 30 audited receipts exist.

## §6 The guard

`scripts/check_pr_review_receipt.sh`. Mutation-verified **before** anything consumes it.

### §6.1 Positive control, first

Before validating anything, the guard validates a deliberately malformed receipt and requires a non-zero exit. If a malformed receipt passes, the guard's own GREEN is a count of files, not a verdict, and it fails the run. (Same idiom as `dogfood.sh`'s `pv validate` positive control.)

### §6.2 Schema gate

```bash
check-jsonschema --schemafile schemas/in-toto-statement-v1.json \
  evidence/pr-review/$PR/$SHA/receipt.intoto.jsonl
check-jsonschema --schemafile schemas/sarif-2.1.0.json \
  evidence/pr-review/$PR/$SHA/findings.sarif
```

Schemas are **vendored** under `schemas/` with a recorded SHA-256. Fetching a schema over the network at gate time makes the gate depend on an external service — the same defect class as the render path.

### §6.3 Fixture table

Every row a committed fixture under `tests/fixtures/pr-review/`, exercised by `bats-core`.

| # | fixture | verdict |
|---|---|---|
| 1 | `cuda.status: not-triggered` on a diff touching `src/cuda/` | RED |
| 2 | `mutation.attempted: 0` with `status: consulted` | RED |
| 3 | finding `grounding: cited` with empty `source` or `excerpt` | RED |
| 4 | comparative claim `grounding: cited`, no comparator command/hash | RED |
| 5 | `pmat.status: unreachable`, `verdict: PASS` | RED |
| 6 | `pmat.status: unreachable`, `verdict: DEGRADED` | **GREEN** |
| 7 | honest receipt, docs-only PR, all consultations `not-triggered` | **GREEN** |
| 8 | `reviewer_actor == author_actor` | RED |
| 9 | `index_commit` not an ancestor of `head_sha`, `verdict: PASS` | RED |
| 10 | `base_sha` ≠ `git merge-base origin/main head_sha` | RED |
| 11 | finding with empty `failure_scenario` | RED |
| 12 | `excerpt_sha256` ≠ `sha256(excerpt)` | RED |
| 13 | valid receipt, invalid signature | RED |
| 14 | complete receipt on a GPU PR, all four consulted, findings present | **GREEN** |

Rows 6, 7, 14 are **discrimination cases**. Without them, "refuse every receipt" reads green — the over-reach a discrimination case already caught in PERF-055 and the #2766 delta-gate work.

**A missing receipt is RED, not skipped.**

### §6.4 Guard mutation set

Fourteen fixtures is a floor, not adequacy. Additionally:

```bash
cargo mutants --file scripts/check_pr_review_receipt.sh   # or: scripts/mutate-guard.sh
```

Mechanically flip each validation branch and drop each required-field check. **Target: 100% kill. Surviving mutants are named in the receipt for the PR that adds them.** A mutation score below 100% on the guard blocks — this is the one place §7's narrowness does not apply, because the guard is the thing every other verdict rests on.

## §7 Blocking policy

| verdict / class | feature branch | release branch |
|---|---|---|
| missing / invalid / unsigned receipt | **BLOCKS** | BLOCKS |
| `reviewer_actor == author_actor` | **BLOCKS** | BLOCKS |
| guard mutation score < 100% (guard-touching PR) | **BLOCKS** | BLOCKS |
| `unverified_comparative_claim` | **BLOCKS** | BLOCKS |
| breaking API surface with no semver bump | **BLOCKS** | BLOCKS |
| stale index (`index_is_ancestor: false`) with `verdict: PASS` | **BLOCKS** | BLOCKS |
| `FINDINGS` (everything else) | proceeds, posted as comment | **BLOCKS** |
| `DEGRADED` | proceeds, marked in first line of comment | proceeds, marked |
| `PASS` | proceeds | proceeds |

The blocking tier is five objective, machine-decidable classes. None of them is a judgement call, so none of them can freeze an active investigation the way #2766 and #2757 did.

**Admission rule for the blocking tier:** a class may block only while its measured precision on the rolling sample is ≥90% — Tricorder's ≤10% effective-false-positive bar. A class that falls below is auto-demoted to advisory by editing `contracts/pr-review-skill-v2.yaml`, not by disabling the gate. Demotion is a ticket, not a silent config change.

## §8 Instrumentation — measure before you ratchet

No threshold below is invented. Each is `instrument → 30 samples → ratchet`.

| metric | definition | initial | ratchet rule |
|---|---|---|---|
| `actionable_rate` | findings the author acted on ÷ findings posted | record only | after 30 PRs, floor at measured − 5pp, monotone |
| `effective_fp_rate` | per blocking class | record only | must be ≤10% to stay blocking |
| `audit_divergence` | second-reviewer disagreement rate | record only | after 30 audits, set sampling from it |
| `cost_per_actionable` | tokens + wall-seconds ÷ actionable findings | record only | ratchet down quarterly |
| `guard_mutation_score` | killed ÷ attempted on the guard | **100%** | zero — no ratchet, it is a one |
| `receipt_presence` | PRs with a valid receipt ÷ PRs merged | **100%** | zero |
| `unmarked_claims` | claims with no grounding mark | **0** | zero |
| `vacuous_consultations` | `status: consulted` with `attempted: 0` | **0** | zero |

Four zeros/ones (jidoka: the line stops on a defined defect). Four instrument-first continuous parameters (kaizen: ratchet the measured baseline, never invent it). `pmat` logs the cost fields; feed them to the routing calculator already in use.

## §11 Failure modes this design prevents

| failure mode | prevented by | evidence |
|---|---|---|
| Device semantics asserted from stale memory | §3.B mandatory consultation | 18% regression on an ungrounded stream claim |
| "Source said nothing" ≡ "didn't ask" | §3.0 SARIF three-state, `no-authority-found` | #2754, #2779, #2780, #2790 |

| Re-implementing what exists | §3.A `duplication_hits` | PERF-055, ~7,200 lines across 46 files |
| Competitor claim with no source | §3.C.1, blocking | *"2.93× Ollama"* from a harness that never ran Ollama |
| Diff scope polluted by other agents' merges | §2 `merge-base` | parallel-worktree agent workflow |
| Index answers about code not in the PR | §3.A ancestor check, fixture row 9 | 66-commit index drift |
| Guard that cannot fail | §6.3 + §6.4, 100% kill | the epic's most common defect class |
| Guard that blocks work instead of defects | §7 five objective classes | #2757, #2766 |
| Review that "passes" without doing anything | fixture rows 1, 2, 11, 14 | — |
| Self-review that flatters itself | §5, fixture row 8 | Huang et al. ICLR'24; self-preference bias |
| Signed receipt mistaken for an honest one | §4.3 stated plainly, `L1-self` | R1 |
