# CB-200 at 0.68.0: the +2 is real debt, and 2 of the 3 additions are outside `crates/`

PMAT-1098. Measured 2026-09-17 on the intel workstation with **pmat 3.40.2** (the version
the box now runs; `.pmat-gates.toml` records the 602 baseline as re-measured 2026-09-15
under 3.40.1).

## 1. Version delta, or real debt?

`.pmat-gates.toml:97-103` holds `[tdg] baseline = 602`. The T-2 pre-publish dogfood read
604 and called it 2 over. A count that moves when the instrument moves is not debt, so the
first question was whether 3.40.1 -> 3.40.2 changed the reading. It did not:

| Tree | Commit | pmat | CB-200 reading |
|------|--------|------|----------------|
| baseline (last `origin/main` commit of 2026-09-15) | `7ee0ecaad` | **3.40.2** | **602** definitions below B across 481 files — `Warn`, at baseline |
| head (`origin/main` @ measurement) | `94df98834` | **3.40.2** | **604** — `Fail`, 2 over |

Both readings come from `pmat comply check --checks CB-200 --format json` run in two
worktrees under `/mnt/nvme-raid0/agent-wt/`, each with its own index
(`~/.cache/paiml-mcp-agent-toolkit/comply/index/<dir>-<hash>/context.db`; pmat indexes
outside the tree, #1008). Same binary, same invocation, only the tree contents differ.

**Verdict: real debt.** The baseline commit reads 602 under 3.40.2, so the +2 is code that
landed on 2026-09-16, not an instrument artefact. A re-baseline would have hidden it.

where tdg_grade in ('B-','C+','C','C-','D','F');

across **481 files** at the baseline (the report states both), 604 at head — so the roster

## 3. What this change fixes: one of the three

`from_model_and_layers` is in scope and is fixed here by extraction only — same inputs,
same outputs, existing tests unchanged:

| definition | before | after |
|---|---|---|
| `from_model_and_layers` | **C+**, cyclomatic 15 | **A+**, cyclomatic 4 |

The extracted helpers each grade at or above the gate's minimum, so the fix does not move
debt sideways: `metadata_usize` A (5), `metadata_usize_or` A+ (1),
`rope_sections_from_metadata` A (5), `qwen35_ssm_meta` A+ (1), `own_deltanet_layer` A+ (1),
`own_attention_layer` A+ (1), `attention_head_dim` A+ (3). After the change
`forward_qwen35.rs` has **zero** definitions below B.

The function had no test (it needs a real hybrid GGUF). The extraction creates a seam that
does not: `qwen35_ssm_meta` reads the Gated DeltaNet shape out of a metadata map, so
`mod qwen35_ssm_meta_tests` (4 tests) pins the defaults, the `qwen2.*`-wins-over-`qwen35.*`
precedence, the non-integer-falls-through-to-default rule, and the per-section RoPE
defaulting — the four behaviours the old inline closure chain encoded and nothing asserted.

Reading after the fix: **603** — `Fail`, 1 over. The roster diff at that point is exactly
the two `.cpp` producers (and the same one removal).

## 4. The remaining 1 is outside this ticket's scope — an orchestrator decision

The last addition is a pair of C++ programs under `evidence/`, of which the F-graded
`apr_raw_logits.cpp:139 main` is the one still over the line. They are not shipped code:
they are the llama.cpp `d1d3c3396` reference harness that produced the Qwen3.5 CPU parity
evidence, vendored so the measurement is reproducible. `scope_paths` for PMAT-1098 covers
`crates/**/src/**/*.rs` and `crates/**/tests/**`; `evidence/**` is neither, and the scope
was not widened.

Note what is *not* an argument here: the gate's universe is already repo-wide, not
crates-only — at the 602 baseline it counts 6 definitions under `experiments/`, 4 under
`scripts/` and 2 under `tools/`. So "it isn't under `crates/`" does not by itself make the
count wrong. The open question is narrower: **should a vendored reference harness, kept
verbatim so a parity measurement can be reproduced, be graded as this repo's debt?**

Three ways to close it, in the orchestrator's hands:

1. **Refactor `apr_raw_logits.cpp`** — splits `main` into helpers. Cheapest to the count,
   but it edits the artefact whose value is that it is the program that produced the
   evidence; a rebuilt binary is no longer bit-for-bit the one cited.
2. **Exclude `evidence/**` (or the producer directory) in `[tdg] exclude`** — states the
   policy explicitly. `.pmat-gates.toml` is not editable under this ticket, and an exclude
   silently drops `raw_logits_compare.cpp` too.
3. **Re-baseline to 603** — *only* legitimate if option 2's policy is rejected, i.e. if the
   `.cpp` debt is accepted as debt. A baseline may only go down, so this would be a
   deliberate ratchet release, and the gate text refuses it as the default answer.

Not a fourth option: raising the baseline to 604 to make the original report green. That
would also have absorbed the `from_model_and_layers` regression, which was real and is now
fixed.

## 5. Reproducing

```bash
git worktree add --detach /mnt/nvme-raid0/agent-wt/cb200-base-7ee0ecaa 7ee0ecaad
cd /mnt/nvme-raid0/agent-wt/cb200-base-7ee0ecaa
pmat comply check --checks CB-200 --format json   # -> 602, Warn
# and in the head worktree -> 604 before this change, 603 after.
```
A re-run in the same directory reuses the index (~12 s); a first run, or a run after
`rm -rf` of that index directory, costs ~80 s. Delete the index directory before trusting
a reading taken after the tree changed.
