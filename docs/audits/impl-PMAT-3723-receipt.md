## Design (one seam)

- `realizar::chat_template::EmbeddedChatTemplate` (`crates/aprender-serve/src/chat_template_embedded.rs`) renders the model file's own template (GGUF metadata, a sibling `tokenizer_config.json`, APR metadata) with minijinja configured the way HF's environment is: trim_blocks, lstrip_blocks, pycompat, loop_controls, `raise_exception`, `strftime_now`, and a Python-`json.dumps` `tojson`.
- `format_chat_prompt(embedded, model_name, messages, thinking) -> ChatPrompt {text, thinking}` is the ONE production entry point: run, chat, serve, code, and the golden gate. A hand-coded template is the fallback only for a file that ships none.
- Thinking modes are DERIVED by rendering: render(on) ≠ render(off) → Both; a render that leaves `<think>` open → OnOnly; otherwise OffOnly. `resolve(None)` gives OFF where the template allows it (#3723 done_when 1, "Default = OFF"). A mode the template cannot honour is `RealizarError::ThinkingModeUnsupported`: apr exit 15, serve HTTP 422.
- `ChatPrompt::split` separates reasoning from answer. A block still open when the budget is spent is an error naming the budget (#3720 `think_block_unclosed`), never an empty answer.
- #3801: `ChatPrompt::generate_with_think_budget(max_tokens, generate)`. Reasoning still open at 3/4 of the budget is closed with `\n</think>\n\n` and the answer is generated after it. `reasoning_truncated` reports it, never silent. `InferenceConfig::raw_prompt` tokenizes an already-rendered continuation as it is.
- Untrusted templates (GGUFs come from the internet): minijinja fuel 5,000,000, a 4 MiB output cap (`CappedOutput`), and a recursion limit; a template over a limit is refused by name.
