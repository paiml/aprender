## What landed

- **`ontology/extract/gguf.rs`** — two inputs, one vocabulary: the ladder contract's `rungs[]` (a contract with `entity: {type: gguf}`) become `model:Model` nodes keyed by `sha256` (`…/v1alpha1/model/<sha256>`; `model:RequiredModel` too when `required`), carrying `model:id`, `arch`, `file`, `backend`×, `host`× (when `hosts:` is listed), `required`, `contract`; a contract whose `entity.ref` names a readable GGUF yields a node from the header (in-house reader: magic, version 2/3, tensor count, the KV stream walked for `general.architecture` and `general.file_type`, every other value type skipped by width, unknown types refused by number) with the file's measured sha256. `positive_control()`: a corrupt magic is refused.
- **`ontology/extract/apr_model.rs`** — the `.apr` v2 container read in-house (no `apr-format` dependency in the leaf crate): the 64-byte header, the CRC32 over bytes 0..40 ++ 44..64 exactly as `AprV2Header::compute_checksum` concatenates them (checked against the IEEE check value), and the tensor index walked entry by entry between `tensor_index_offset` and `data_offset` so the header's count is compared with what the file holds. `golden_v2.apr` parses (2 tensors); `lie_about_tensor_count()` makes the positive control — count +1, checksum recomputed, refused as `header says 3 tensor(s), the index holds 2`. The committed fixture `tests/fixtures/ont/ladder-lyingapr/models/lying.apr` IS those bytes (a test asserts equality; it was generated once by a 40-line standalone rustc program in the session scratchpad, no Python).
- **`ontology/receipts.rs`** — `resolves: receipt`: one reader for `apr-model-ladder-receipt/v1` (any other schema refused by name); witness / hex mismatch / unmeasured row per (rung, row) materialized as `model:parityReceipt` edges to `model:Receipt` nodes (`receiptHost`, `receiptVersion`, `cc` as a string, `gpu`, `green`, `capabilityPassed` = passed ∧ ¬skipped, `backendsOk`, `receiptSha256`, `backendRan` per backend), `model:receiptHexMismatch "<file>: <hex>"`, `model:unmeasuredRow`, and per rung `model:greenOn`/`model:missingGreenHost` over the hosts the rung lists (or every host with a receipt). The whole quantification lives here so the shapes stay in §3.6's subset.
- **`ontology/shapes.rs`** — `parse_shapes()`: `shape:` (id = stem) and/or a `shapes:` list with an `id` each (repeats and missing ids malformed); `maxCount` messages now NAME the values (up to five) — a `maxCount 0` on a materialized edge is only actionable when the message says which host, which file.
- **`ontology/arming.rs`** — `ArmedShapes::{All, Listed}` from `armed_shapes[]` (absent = All), `check_shapes_monotone` (`armed_shapes shrank: <names>`, exit 3 via `contract_walk`); an `All` comparand is judged against the shapes declared in files that existed at the comparand (`lint_arming.rs` asks git), so a shape in a new file may ship reported-first.
- **`lint/shapes_gate.rs`** — `extract_graph()` (every extractor + the receipts, shared with `pv extract`), per-shape arming in the verdict (unarmed results are findings marked `[not armed]`, counted in `unarmed_violations`, never in the meet), the plant must fire from an armed shape, `decline()` for NoFocus / NoReceipts / PositiveControlFailed(which), `findings_of()` naming the rung, PV-ONT-012 for extractor rejections. `GateExtra::Shapes` gains `armed_shapes`, `not_armed_shapes`, `unarmed_violations`, `by_entity_type`, `pc_extract`, `receipts`, `witnesses`, `hex_mismatches`, `unmeasured_rows` — all at the top level of the single-gate JSON, where the spec's probe reads them.
- **`contracts/ont-model-receipts-v1.yaml`** — both shapes: `ladder-measured` (`model:sha256` min 1 max 1 pattern, `model:parityReceipt` min 1 IRI class `model:Receipt` `resolves: receipt`, `model:receiptHexMismatch` max 0) and `ladder-green` (targetClass `model:RequiredModel`: `model:missingGreenHost` max 0; `model:parityReceipt` → node with `model:cc in ["8.9","12.1"]`). `contracts/model-capability-ladder-v1.yaml` gains `entity: {type: gguf}` and nothing else. ## Why this PR merges after the receipt PR

On this tree the tracked receipts (`evidence/dogfood/models/0.68.1/{lambda,gx10}.json`) predate #3507: no rung row carries `sha256`, so every rung has zero witnesses and `ladder-measured` — armed — fails all eight. That is the correct reading (a measurement nobody made is not a match), and it is why `lint_passes_on_real_contracts` and `the_repo_corpus_passes…` are red on this head and `make contracts` would be too. The release session is running the ladder on both hosts with #3507's script after #3511 and committing the re-measured receipts; this branch rebases onto that, `pv extract` is re-run (the graph gains the `parityReceipt` edges), the two tests go green, and the quorum judges that head. Merging before it would put a red gate on main; merging after it puts an armed gate with a witness for every rung.

## Deviations, named

- **`Unknown{ReceiptUnmeasured}` is not a lattice element.** The spec row names it; ONT-6's lattice has 15 Unknown reasons, contract-bound (`ont-verdict-lattice-v1`, |V| = 17, Kani-proved), and adding one would ripple through that contract, its tests and spec §3.4. The no-receipts case declines `NoCheckable` with the WHY printed beside it (`shapes: N shape(s) resolve receipts and the tree holds none under evidence/dogfood/models/`) — the ONT-4 precedent (zero typed relations → NoCheckable), and it closes the owed "NoCheckable says nothing" for this gate. Spec text to be corrected in v4.7.
- **`ont.shapes_unarmed` is recorded, not ratcheted downward.** The spec's §3.9 sentence says "ratcheted downward like `legacy_unresolved_depends_on`"; a downward ratchet would refuse every new shape that ships reported-first — the mechanism §3.9 exists to allow. It is written into the baseline by `--write` so a change is a diff a reviewer sees. Spec text to be corrected in v4.7.
- **`sha2` added to `aprender-contracts`** — a workspace-pinned crate `pv` already links (the CLI crate depends on it); no new external crate enters the tree.
- `goal.sh set` refused; k measured from the transcript: **132 at this receipt** from the branch/ticket to here — K̂ was 60.
