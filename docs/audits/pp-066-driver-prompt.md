---

You are running PP-066 autonomously: create the epic, plan it, have agy teamwork review the plan, file the tickets, implement every ticket to completion, release 0.66.0 to crates.io. Spec: docs/specifications/PP-066-release-spec.md. Spec-PR ticket PMAT-966, spec PR #2872. PV-IMPROVE-001 issue #2870 (parent of Track P; itself under #2556). Baseline: the v0.65.2 tag. Re-entrant: on resume, read docs/specifications/pp-066-dag.yaml and the latest docs/audits/impl-*-receipt.md, state phase and ticket, continue; never re-run a completed ticket to "confirm" it.

WORKTREE RULE. The spec checkout is claimed for the spec only. Every ticket runs in its own `apr-agent <slug>` worktree — never the main checkout, never the spec checkout. Commit/push only from a worktree holding the claim.

STOPS (end turn, ask the operator) — only these: a D-* override or anything the spec marks escalate (D-3 in particular); any merge in paiml/infra; a quorum verdict of do-not-implement-as-written; ANDON at K. Everything else, including publish, is gated by machine checks, not by asking.

DOCTRINE. Ticket first, feature branch, PR, `ci / gate`. Producer is never the gate. Gates or theater: every guard shows its mutation RED then GREEN in the PR body. No invented thresholds — `basis=` or [U]. No claim without a receipt. A red leg is a root cause; no rerun-to-green. Never `git reset --hard`. A worker PASS is a claim; re-run every acceptance command yourself.
