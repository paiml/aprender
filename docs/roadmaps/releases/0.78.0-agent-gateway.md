## 2. Exit (done_when)

**Measurement:**
- **Host and model:** lambda 4090; Qwen3.5-4B Q4_K_M, one GGUF read by its sha256.
- **Comparison:** llama.cpp's server (pinned) and ollama (pinned), run on the same GGUF.
- **Receipts:** under `evidence/agent-gateway-078/<date>/`.
- **Exit codes:** 0 PASS (GREEN), 1 FAIL, 2 NOT_MEASURED, 3 YELLOW. NOT_MEASURED counts red.
- **Binary:** pinned with `scripts/apr_bin.sh`.
- **Sampling:** accuracy cells (A1, A2b) run each engine at temperature 0.7 with seeds 1–5, so each engine yields 5 per-seed accuracies; the 95% CI is a t-interval over the 5 per-seed differences. Equality cells (A5) use greedy decoding.

**Fixture suites, Rust, checked in under `crates/aprender-serve/tests/fixtures/agent-gateway/`:**
- **T50:** 50 tool-call cases (single, multiple-choice, parallel, no-call), each with the expected function name and arguments. A case is correct when the returned call set equals the expected set by name and by JSON-equal arguments (a no-call case is correct only with no call).
- **J50:** 50 JSON schemas with prompts.

**Exit cells:**
- **A1 OpenAI tool calls (C-11, I-03):**
  - GREEN: on T50, 100% of returned `tool_calls` parse and validate against the request's tool schema as returned to the client (a call repaired server-side counts as valid only if AG-10 chose repair and the receipt counts repairs separately) **and** the lower bound of the 95% CI of (apr − llama.cpp) accuracy is ≥ −5 points.
  - YELLOW: schema-valid 100%, and the CI straddles −5.
  - RED: any schema-invalid call, or the CI's upper bound is below −5.
- **A2a ollama tool shape (I-04), expected green:** distinct from 0.77's C-04 (SP-13), which diffs a plain chat response; A2a diffs the `tool_calls` fields. GREEN when the live `/api/chat` tool response has the same key set as the pinned ollama's response to the same request (key diff); otherwise RED.
- **A2b ollama tool accuracy, expected yellow or red:** scored as A1, against ollama instead of llama.cpp.
- **A3 structured output (C-10, I-12):**
  - GREEN: on J50, `response_format: json_schema` returns 100% schema-valid JSON, and `falsification_crux_i_12.rs` (schema→grammar) passes. Otherwise RED.
  - llama.cpp's valid rate on J50 is reported beside ours, not scored.
- **A4 agent loop (I-02, I-06):**
  - The agent runs 10 scripted tasks that require calling a tool served by an external stdio MCP server (a fixture server in Rust).
  - GREEN: ≥8/10 tasks complete (a task is complete when its fixture check script exits 0 on the final state), and the loop stops on its max-iteration and stop conditions in the I-06 receipt. Otherwise RED. A capability cell; no competitor ratio.
- **A5 multi-LoRA serving (C-16, C-17), expected green or yellow:**
  - `apr serve --enable-lora` on the C1 base (Qwen2.5-Coder-1.5B-Instruct) with two adapters loaded, both trained by the 0.76 C1 recipe.
  - **Reference:** the same server with only that one adapter loaded, served one request at a time.
  - **Equality:** 20 prompts per adapter, sent concurrently and routed by `X-LoRA-Adapter`, return the reference's first 64 token ids exactly (greedy).
  - **Non-vacuity:** each adapter's output differs from the base model's on at least 1 of the 20 prompts, or the cell is RED.
  - Load and unload without a restart (C-16).
  - GREEN: all of the above, with the batched adapter kernel (AG-44) serving the concurrent requests. YELLOW: all of the above, but served one request at a time. RED otherwise.
- **A6 wire compatibility (K-01..K-04, the Rust side only):**
  - GREEN: every `/v1/chat/completions` response in A1/A3 validates against OpenAI's published response schema, vendored with its source URL and date; and, if AG-22 lands, every streaming chunk does too.
  - If AG-22 is cut, A6 checks non-streaming responses only; its colour is set by those, and streaming is reported NOT_MEASURED beside it.
  - RED: any response (or, with AG-22, any chunk) fails the schema. A6 has no YELLOW.
  - The K rows themselves stay NOT_MEASURED (red) unless AG-30's quorum receipt allows a pinned external harness.
- **A7 browser (in-tree `BrowserTool`), stretch, LAB.** Not J-09: `contracts/crux-J-09-v1.yaml` asks for an external browser-automation MCP server, which stays with #6496.
  - The agent drives `BrowserTool` on a localhost fixture page with its existing verbs: navigate, click, then evaluate to read a value back.
  - LAB, so it cannot block anything (GATE/LAB rule); a red opens one ticket.
