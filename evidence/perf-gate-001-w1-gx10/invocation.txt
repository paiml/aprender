--------------------------------------------------- deviations from PR #2831 --
1. `--tokenizer-sha256` was NOT passed. PR #2831 passed it and recorded, as its
   defect 1, that it is SILENTLY DROPPED under --tokenization server_usage. The
   flag is not part of the briefed argument set for this cell and passing a
   known no-op only to re-observe it is not evidence. The receipts' tokenization
   block is identical to lambda's either way.
2. The producer's EXIT STATUS was not captured. It was launched under nohup in
   the background so the run would survive the control session, and the exit
   status was lost with the subshell. Completion is evidenced instead by all
   three receipts being written, the terminal "next" block appearing in stdout,
   and an empty stderr -- which is weaker than lambda's recorded `exit status 0`
   and is recorded here as weaker rather than asserted as equivalent.
3. server-startup.txt is the startup section only (67 lines, through the second
   "Press Ctrl+C to stop"). This build emits per-request [PMAT-072]/[PMAT-075]
   debug lines that lambda's log did not carry, so the raw log reached 1224
   lines / 133 KB. NOTHING WAS DISCARDED: the complete unmodified log is
   retained as server-full.log.gz beside it.
