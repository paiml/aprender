# tool_version=none (grep over git ls-files crates/*/src/**.rs; not a versioned analyser)
# Lib-test assertions that an INTEGER duration is positive (`> 0`, `>= 1`, `!= 0`) which PREDATE
# check_no_timing_in_required.sh PART 4 (#3703, 2026-09-21). That shape fails on a fast host: an
# `as_millis()` taken over sub-millisecond work reads 0. It stopped the v0.69.0 clean-room on
# gx10-pool1 (aprender-verify-ml test_pipeline_generate_small), and three such lines were FIXED in
# the same commit rather than recorded (pipeline.rs, bug_hunter tests_patterns.rs, instruct_trainer.rs).
#
# Every occurrence below was read and classified. None measures elapsed time that can truncate to 0:
# each is a declared constant, a configured value, an epoch timestamp, an estimate, a fixture input,
# or a real measurement taken AFTER a sleep of at least the unit it is truncated to.
#
# FORMAT: `<assertion text, trimmed><TAB><occurrences across crates/*/src>`. The key is the TEXT,
# never a coordinate. A `<path>:<line>` key goes stale on any edit above the line, and re-pointing it
# is an addition the shrink-only ratchet refuses unless the guard itself changes, so an unrelated
# one-line edit in any of ~50 files would have turned guard-tree red with no in-branch remedy
# (measured on this branch before it was re-keyed). Keyed on text, a move, an insertion above, or a
# file split changes nothing here.
#
# THE RATCHET (`keyed`): no key may appear and no count may rise. So a NEW timing-shaped assertion
# fails, and so does a COPY of a recorded one (the count rises): assert what the code promises
# instead, e.g. `assert_eq!(budget.total_ms, 16)`, never `> 0`. PART 4 also fails when a count here
# exceeds the tree (fixed or edited lines): lower or delete the entry in the same commit, which the
# ratchet allows. Editing a recorded line's text is a new key: fix that assertion rather than record it.
