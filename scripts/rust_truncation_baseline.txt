# rust_truncation_baseline.txt -- #3916, the Rust half of the surface #3904 ratchets down.
#
# #3904 refuses a NEW silent truncation of a value a human reads later, and its scan matches
# `[:N]` -- Python. Rust truncates with `.chars().take(N)`, and #3904 is blind to every one.
# That blindness was found the hard way: a `.chars().take(100)` in the golden gate's own
# failure reason cost a diagnosis during #3914, and the guard built for exactly that class
# could not see it.
#
# THE RULE IS #3904's, UNCHANGED: never truncate SILENTLY. The dividing line is whether a
# human reads the string later, DETACHED from what produced it.
#
# THREE LEVELS, because the Rust corpus has a middle one the Python corpus did not:
#   display    cut, and the reader cannot tell. THE CLASS THAT MATTERS.
#   marked     appends "..." -- the reader knows it was cut, but not by how much. That
#              solves the AMBIGUITY (a decapitated message no longer reads as a complete
#              short one) without solving the MAGNITUDE. A real improvement over `display`
#              and a real shortfall against `loud`, so it is its own class rather than being
#              rounded to either. Calling these `loud` would contradict #3904's own check
#              next door, which requires a COUNT -- two guards disagreeing about what the
#              word means is worse than a missing class.
#   loud       says HOW MUCH it dropped. The sanctioned pattern.
#   id-prefix  a deliberate short sha/commit/key; the convention carries the length.
#   fatal      dies immediately -- reader present, context still on screen.
#
# `marked` and `loud` are both CHECKED, never taken on trust: a row claiming either must
# demonstrably contain its marker or its count. An unverified class is an exemption keyword.
#
# SCOPE IS MEASURED. `.truncate(N)` is OUT: all 26 receivers in this tree are collections,
# and String::truncate / Vec::truncate are syntactically identical with only the TYPE
# separating them. Read the scan's docstring before "closing the gap".
#
# KEY = <file>|<sha1-8 of the normalized line>|<n-th identical line>, #3904's scheme
# deliberately -- a third bespoke baseline format is its own debt. Keying by file:line
# produces churn on any insert, and churn trains a reviewer to regenerate the baseline,
# laundering whatever real violation shares that commit. The key hashes the text, so the
# text below is tamper-evident.
#
# SHRINK-ONLY, and NO --update, for #3904's reason: only KEY and TEXT are derived, the CLASS
# is a human reading no command reproduces, and a regenerate button is the laundering vector
# the key scheme exists to close.
